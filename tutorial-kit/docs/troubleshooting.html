Troubleshooting

First open Tools > All In One Tutorial Kit > Why Is This Step Waiting while playing, and Scene Overview in the editor: they say what is wrong in plain words, and Scene Overview fixes most of it in one click.

The tutorial doesn't start. It may have run before: with Run Once Per Player on, a finished or skipped flow never runs again for that player. Press Restart in the flow's Inspector while playing. Or its Start is Manually: something has to call Play (a Tutorial Trigger, a button, a UnityEvent).

A step never finishes. The debugger says what it waits for (the step's Inspector says it too). A step with no rule needs its Next button (Next Button: Auto or Show). A Click Target step on a button that isn't interactable waits until the button can be used. An Input Action rule waits forever if your game has turned that action's map off: the debugger says so.

A step doesn't show at all. Its target isn't there yet (a closed menu, an object not spawned yet): with When Target Missing: Wait, the step waits for it without showing or blocking anything. The debugger says "Hidden while its target isn't there".

The spotlight is in the wrong place or missing. The target isn't set, is turned off, isn't under a Canvas, or (for UI Toolkit) no element has that name. For world objects, set the step's Camera when you use several cameras.

Clicks on the tip card do nothing. The scene needs an EventSystem. The kit adds one when Play starts; Scene Overview can add it in the editor.

My game's buttons can't be clicked. That's the Input Gate: Only Target lets only the spotlighted target through. Set it to Allow All, or use the Hint style.

The card is behind my UI. Raise the flow's Sort Order (above your highest canvas; the highest is 32767).

My pause menu opens behind the tutorial. Call TutorialFlow.SuspendAll(true) when it opens and false when it closes.

Escape skips the tutorial and opens my pause menu. Set the flow's Skip Key to None (the default for new flows).

A gamepad can't press the highlighted button. The scene's EventSystem needs an input module for your gamepad. The kit selects the highlighted button for gamepad players, so Submit presses it.

Typing in a text field finishes a Key step. The kit ignores keys while a uGUI Input Field (or TextMeshPro's) has focus. For other text input, add TutorialInput.AddTypingCheck(...).

The tutorial highlights an item hidden in a scrolled list. Scroll Into View (on the target, on by default) scrolls uGUI Scroll Rects. UI Toolkit ListViews reuse their rows, so scroll the list yourself (ScrollToItem) and point at the list itself, or at a row by a name you set when you bind it.
