Docs/Tutorial Kit/Features

Targets

Each step points at one target. The spotlight, outline and pointer follow it every frame, so moving and animated targets are fine.

Kind Set Notes
None nothing A plain message in the middle of the screen.
UI Element a uGUI RectTransform (button, icon, panel) Any canvas mode; clicks on it can finish the step.
UI Toolkit Element a UI Document and an element name (or a USS class) Names as set in UI Builder.
World Object any object Uses its renderers (3D meshes, sprites), else its 3D or 2D colliders, else its position.
Screen Area a rectangle as fractions of the screen 0,0 is bottom left, 1,1 is top right.
Found By Id an id, like shop.buy For things that don't exist yet when you build the tutorial (see below).

Spawned, pooled and list items: Found By Id #

Menus built from prefabs, inventory slots, pooled UI and objects in other scenes can't be dragged into a step. Instead:

  1. Add Add Component > All In One Tutorial Kit > Tutorial Target Id to the object or prefab, and type an id (inventory.sword).
  2. Set the step's target to Found By Id with the same id.

The step waits until an active object with that id exists, then highlights it (a uGUI element like UI Element, anything else like World Object). If the object is turned off or returned to a pool, the step hides and waits again; the newest active object with the id wins. Use a different id for each thing a step should point at (20 inventory slots from one prefab need 20 ids, or set the id by code). From code: TutorialTargets.Register("shop.buy", button.transform) and Unregister.

Clicks #

On a button (or any Selectable), only a click the button really takes counts: a click on a button that isn't interactable doesn't finish the step. Gamepad and keyboard Submit on the highlighted button counts too, and gamepad players get the highlighted button selected. On a plain panel or picture, a press and release inside it counts.

Lists: Scroll Into View #

A uGUI target inside a Scroll Rect (a shop list, an inventory) is scrolled into view when its step starts, so the spotlight never points at an item the list's mask hides. Turn Scroll Into View off on the target to leave the list alone.

World objects #

  • Bounds chooses what the highlight wraps: Auto, Renderers, Colliders, or Position (with a size you set).
  • Camera: the camera that sees it. Empty uses the main camera, or the first camera that sees the object. For split screen, set the player's camera here. Cameras that render into a Render Texture aren't supported.
  • When the object is behind the camera or outside the view, the pointer sits at the screen edge and points toward it.

When a target can't be found #

When Target Missing on the step decides (the menu is closed, the object isn't spawned yet, it was turned off):

Choice What happens
Wait (default) Nothing shows and nothing is blocked until the target appears, then the step shows. The game can never get stuck behind a dim screen.
Show Card The card shows in the middle of the screen without a highlight.
Skip Step The step is passed over.

Why Is This Step Waiting and Scene Overview say what is wrong: not set, turned off, not under a Canvas, no element with that name, no object with that id yet, or no camera.
