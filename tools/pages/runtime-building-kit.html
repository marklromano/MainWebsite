All In One Runtime Building Kit

Let your players build bases and place furniture while they play. Turn your own model into a build piece in about ten minutes, with no code. Pieces snap together through sockets, and every spot that's refused says why, in plain words: "Overlaps Wall_03", "Needs 4 Wood (you have 2)", "Keep the path clear".

How it works

From your model to a placed piece in three steps

  1. Make it buildable

    In Tools > All In One Runtime Building Kit, drop your model or prefab into Make Buildable, check the measured size, pick a preset and click Create Piece. Your model is never changed.

  2. Test it

    Test in Play Mode opens a test scene with your piece ready to place. Place a second one and it snaps to the first.

  3. Build in your game

    Add a Build World to your scene and a Builder to your player. The Builder never reads input itself: call it from your own controls, or use the samples' input script.

Features

Building that snaps, costs, saves and says why

Placement that explains itself

Sockets · Grid · Free
  • Sockets first, then the grid, then free placement: walls stand flush on the edge of a foundation, and a floor resting on walls lines up with the foundation below.
  • Every refused spot says why: "Overlaps Wall_03", "Slope 38° (max 30°)", "Too far (12.4 m, max 8 m)", "Hangs over the edge of Table_01".
  • A preview that never triggers gameplay: a see-through copy of the model's meshes only, with no colliders, scripts or physics, green or red.
  • Works with rotated and unevenly scaled pieces and any pivot. Add your own rules, with your own reasons, in C#.

Make it yours

Four themes
  • Classic, Blueprint, Warm and Minimal: one click changes the whole look
  • Change or switch off every part: preview, crosshair, words, hotbar, menu, sounds, effects
  • Every word in one Text Table, ready to translate
  • Your own UI through events; per-piece colours and sounds

Your models, no code

  • Make Buildable measures your model and offers a one-click Scale when it's the wrong size
  • Presets: Foundation, Wall, Floor, Furniture, Wall Mounted
  • Box or Mesh collider for models without one
  • Pieces lists every problem with a Fix button

Furniture and interiors

  • Stands on floors, tabletops and shelves
  • Hangs on walls or from ceilings
  • Needs Support refuses anything hanging over an edge
  • Turn a placed piece where it stands

Costs and sandbox

  • Resource Types and a cost per piece
  • Your own inventory through IResourceProvider, or the included Simple Resource Inventory
  • A refund % when a piece is removed
  • Sandbox mode builds for free

Remove, move, upgrade, undo

  • Remove with a refund
  • Pick a piece up and put it down elsewhere, for free
  • Upgrade in place to the next tier, keeping its links
  • Undo and redo each player's own actions; costs and refunds are reversed exactly

Structure and Build Zones

  • Removing a piece that holds others up is refused ("Holds up Wall_01") or removes them too, as you choose
  • No physics collapse: pieces never fall
  • Build Zones forbid building in an area, or allow it only there, each with its own reason

Saving

  • Versioned JSON saves that name pieces by ID, never by name or path
  • Pieces whose definition is missing are skipped and named
  • Save to the cloud or your own save system through ISaveBackend

Multiplayer

Netcode for GameObjects
  • Host-authoritative: players see their own preview at once, and the host checks every request with the same rules and costs as single player, then sends the change to everyone.
  • Forged requests are refused: the host uses the connection's client ID, checks where the player is, and answers a repeated request once.
  • Everyone sees the same world: late joiners get everything built so far, refusals come back in plain words, and each player undoes only their own actions.
  • An "owner only" permission is included. Another networking library works through IBuildMessenger, and without Netcode for GameObjects everything else works as before.

Build menu

  • Tab, or the gamepad's View button, opens every piece by category
  • Keyboard, d-pad and mouse
  • A Keys page to change the controls, saved between sessions (Input System)

Good to know

Limits, stated up front

  • Multiplayer has one authority, a host or a dedicated server. Netcode's distributed authority mode isn't supported.
  • There is no physics collapse: pieces that lose their support are protected or removed, never dropped.
  • HDRP needs the project in Linear colour space (HDRP's own setup does this); in Gamma nothing is lit.
  • With the old Input Manager, the samples read gamepad buttons only. Sticks, the build menu's d-pad and changing keys need the Input System package.
  • Resource amounts belong to your inventory and are saved by it. The included Simple Resource Inventory doesn't save them.
