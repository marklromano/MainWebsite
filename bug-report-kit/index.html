All In One Bug Report Kit

Testers press one key, say what went wrong, and you get one file that shows it: their words, a marked-up screenshot, the last seconds as pictures, the log with stack traces, recent events, system info and your game's state. Open it in Unity and click straight to the broken line.

Join the Discord Features
  • Unity 6000.0+
  • Built-in, URP & HDRP
  • No dependencies
  • Full C# source

How it works

From "it broke" to the broken line

  1. Import it

    The reporter starts by itself in the Editor and in development builds. No scene setup, no code.

  2. Testers press F8

    The screenshot is taken before the form appears. They pick a category, write a line, circle the problem and save.

  3. Open it in Unity

    The Report Inbox shows every report. Click a stack line to open your script, or jump the Scene view to where the tester stood.

Features

Everything you need to fix a bug you didn't see happen

One file per report

A zip with a readable page inside
  • The tester's words, category and severity, with steps filled in from what they just did.
  • Screenshot with markup (circle, arrow, blur) and a replay of the last seconds as pictures.
  • Console log with stack traces, recent events, system info, scene and camera, your own game state and attached files.

Report Inbox

  • Clickable stack traces that open your script at the line
  • Go to where the tester was, in the Scene view
  • Status, notes, search, filters, CSV export

Debug overlay

  • In-game console with search, level filters and collapse
  • Commands from one attribute, such as help or timescale
  • Frame rate, frame time graph and memory

Debug options

  • Mark a field with [DebugOption] and register it: it appears in the overlay, no UI code
  • Or use the Debug Options Source component, with no code at all
  • Pin any option to stay on screen

Private by default

  • Reports stay on the device; no analytics, no account
  • Testers see and untick every part before saving
  • The computer's user name is hidden; add your own rule
  • Discord and your own server are optional, off until you switch them on

Gone from release builds

  • Development builds only, by default
  • Release builds lose the code that starts it, the Unity UI screens, the input code and the settings; a small core stays so your calls still compile
  • Checked by building release players and looking inside them

Make it yours

Four themes, or your own
  • Studio, Daylight, Terminal and High Contrast, switchable live; your own colours, font, images and text size.
  • Your own words for everything testers read, in one text table. Status messages as words, icons or both.
  • Phones, gamepads and big screens: safe areas, touch gestures, a focus ring on every control, fit-tested on seven screen shapes.

Good to know

Limits, stated up front

  • It hasn't been run on an Android or iOS device or in a browser yet: Android and WebGL scripts build, but aren't tested there.
  • A Discord webhook address in a build can be found by anyone who has the build. Use a private test channel.
  • The replay is pictures, not video, and needs graphics card read-back (not in WebGL).
  • Not yet tested on a phone or with a gamepad, though both are supported.

Status

  • The kit is in its final checks before submission to the Asset Store. Its documentation goes up here the day it launches.
