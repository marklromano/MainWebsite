Builds and privacy

Which builds contain the kit #

Settings > Include In:

  • Development Builds Only (the default): there in the Editor and in builds with Development Build ticked; gone from release builds.
  • Always: in every build, so players can report bugs too.
  • Never: switched off everywhere, the Editor included.

A build that leaves the kit out really leaves it out: the code that starts it, the Unity UI form and overlay and the input code are removed, and the settings (with any Discord or server address) are not in the build. A small core stays so your own calls such as BugReporter.AddBreadcrumb still compile; nothing starts it, so they simply do nothing. This is checked by building release players and looking inside them.

What leaves the device #

Nothing, by default. Each report is a zip in the game's persistent data folder. The kit has no analytics, no telemetry and no account.

If you switch them on in the settings:

  • Discord: each report is posted to a channel through its webhook. Anyone with a build can find the webhook address, so use a private test channel.
  • Your own server: each report is sent as a form POST with the zip and a few fields.

When a send fails, the zip stays on the device and the kit tries again the next time the game starts, up to five times. The form's privacy line says plainly where reports go, and testers can untick any part before saving.

For anything else you must hide, set ReportPrivacy.Redact (see Extending). If your rule fails, the text it was meant to clean is left out rather than saved as it was.
