Adding it to your own game

The kit starts by itself, so in most games there is nothing to do: press Play, then F8. This page is for games that already have their own input, pause menu, cameras, scenes or console, and for the questions that come up when the kit meets them.

To check that the kit itself works, open Tools > All In One Bug Report Kit > Why Isn't It Working while playing and click Open the Form Now. If the button opens the form but F8 doesn't, something in your game is taking the key.

Keys #

Your game What the kit does What you can do
Already uses F8 or the key above Tab Both react Pick other keys in Settings (Open Key, Overlay Key). Set a key to None to switch it off and open the form from your own button with BugReporter.Open()
Has a chat box or a name field Ignores its keys while a Unity UI, TextMeshPro or UI Toolkit text field has focus Nothing
Has its own text entry, rebinding screen or console Can't see it BugReporter.KeysBlocked = () => myChat.IsOpen;
Uses touch gestures A three-finger tap opens the overlay, a four-finger tap the form Switch off Touch Gestures in Settings

Closing the overlay with its key is never blocked, so it can't get stuck open.

Your game's input while the form is open #

The form takes the mouse and keyboard, but your game's own input keeps running underneath: typing "w" in the form can also walk the player forward. Pause it with the kit's events:

void OnEnable()
{
    BugReporter.FormOpened += PauseGameInput;
    BugReporter.FormClosed += ResumeGameInput;
}

void OnDisable()
{
    BugReporter.FormOpened -= PauseGameInput;
    BugReporter.FormClosed -= ResumeGameInput;
}

void PauseGameInput() => playerInput.actions.FindActionMap("Player").Disable();
void ResumeGameInput() => playerInput.actions.FindActionMap("Player").Enable();

The kit unlocks and shows the cursor while the form is open and puts it back afterwards, unless your game hid or locked it in the meantime.

Pausing #

With Pause While Open on (the default), the form sets Time.timeScale to 0 and puts the old value back when it closes. If your game sets a time scale other than 0 while the form is open (slow motion, say), the kit keeps it. If it sets 0 (its own pause menu opening behind the form), the kit can't tell that apart from its own pause and puts the old value back; switch off Pause While Open and pause from BugReporter.FormOpened instead if your game pauses itself. The kit itself runs on unscaled time, so the form and overlay work while your game is paused.

The overlay's timescale command changes Time.timeScale directly. If your pause menu keeps its own "paused" flag, the two can disagree after using it; close your pause menu first.

Scenes #

The kit lives on one hidden object that survives scene loads. A report records the active scene and every other scene loaded next to it. Go to where the tester was opens the same set (asking first if you have unsaved changes) and tells you if one of them isn't in this project.

If your game destroys every object on reset, including ones kept with DontDestroyOnLoad, it destroys the kit's too; call BugReporter.Start() after the reset to bring it back.

Game state providers on objects that are destroyed are dropped by themselves.

Cameras #

The screenshot is always what was on screen. For Go to where the tester was, the kit uses the camera tagged MainCamera, or else the screen camera drawn last (cameras that draw into a texture are skipped). The report names the camera it used. For split screen, a camera rig that isn't tagged, or Cinemachine, tell it which one:

BugReporter.TesterCamera = () => localPlayer.Camera;

With Cinemachine, give the Unity camera that has the Cinemachine Brain, not a virtual camera.

UI #

The form and overlay are drawn on their own Canvases at very high sort orders (31990 and 32000), above almost any menu. They use your game's EventSystem when there is one, and add a hidden one only while one of the kit's screens is showing when there isn't. Your EventSystem and its input module are never changed.

Without the Unity UI package the kit uses a simpler form with no markup; Why Isn't It Working says so.

Your own code and assembly definitions #

If your scripts are in an assembly definition, add RomanoAssets.BugReport to its references to call BugReporter, DebugOptions or [DebugCommand]. Scripts without one (Assembly-CSharp) see it already.

Your calls stay in release builds and do nothing there; you don't need #if around them. Release builds leave out the kit's start-up code, its Unity UI screens, its Input System code and its settings, so nothing starts.

[DebugCommand] and [DebugOption] keep their methods and fields when IL2CPP strips code, so commands work in IL2CPP builds too.

Other consoles and error reporting #

The kit reads the log with Application.logMessageReceivedThreaded, which works next to other consoles, Sentry, Backtrace or your own log handler. If your game sets Debug.unityLogger.logEnabled = false, reports have no log; Why Isn't It Working warns about it while playing. To use only the report form next to another console, switch off Enable Overlay in Settings.

Big logs and attachments #

Each log line and stack trace is kept up to 16,000 characters and the kit keeps the last Log Lines of them (1,000 by default). Attachments over Max Attachment Megabytes (50) are left out with a note in the report. Read a save file into memory when your attachment callback runs, rather than while the game is writing it.

Several game windows on one PC #

Every report file has its own random ID, so several copies of the game (multiplayer testing, ParrelSync) can save to the same folder. Unity sends key presses only to the focused window by default. Put "Host" or "Client" in the game state so you can tell the reports apart:

BugReporter.SetContext("Network role", NetworkManager.Singleton.IsHost ? "Host" : "Client");

Not covered #

Native crashes and hard freezes can't be reported from inside the game. VR, consoles and phones have not been tested on real hardware; for VR, build your own form with BugReporter.UseForm.
