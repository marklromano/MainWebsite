Docs/Bug Report Kit/Using the kit

The report form

Testers open it with F8 (Settings > Open Key), the on-screen Report a bug button, a four-finger tap on a touch screen, or from your code with BugReporter.Open(). The game pauses while it's open (Settings > Pause While Open).

What testers fill in #

  • What happened? The only box they must fill.
  • What did you expect?
  • What did you do before? Already filled in from the recent events, so most testers only check it.
  • Category and Severity, from the lists in the settings. An empty list hides that choice.
  • Screenshot, taken just before the form opened, so it shows the game, not the form. Testers can draw a Circle or an Arrow, or Blur something private. Blur replaces the pixels with flat blocks, so what it hides can't be recovered. Undo takes back the last mark.

What gets saved #

Every part has a tick box, and the form says how much each holds. Unticked parts are left out before anything is written, so they reach no file and no destination.

Part What it is
Screenshot The marked picture
Replay The last few seconds as small pictures (Settings > Replay Seconds)
Console log The last lines with their stack traces (Settings > Log Lines)
Recent events Scene loads, warnings, errors and your breadcrumbs from the last minute
System info Game version, build, Unity version, pipeline, OS, device model, CPU, memory, graphics, screen, quality, language. No user or device name
Game state Values from your Report Context Sources and code
Scene and camera The active scene and the main camera's position, for Go to where the tester was
Attached files Files your code adds, such as the save file

The computer's user name is replaced with <user> in every path (Settings > Hide User Name). The line under the tick boxes says where reports go.

After saving #

The form says Report saved with the file's place, and lists each destination's result. Close it and a short note stays on screen for a moment. With no uGUI package, a simpler form with the same parts and no markup is used.
