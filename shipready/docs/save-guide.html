Shipready: Guide

Version 1.0 · Rare Geometry

This Guide shows how to do things with Shipready, one task at a time: getting started, saving values from your scripts, slots and autosaves, making objects remember their state, the save menu, co-op and Steam Cloud. For how each part works in detail, every setting and every editor tool, see the Reference. New to Shipready? Start with the Quick Start.

Settings in bold, such as Save Version, are fields on the settings asset ShipreadySaveSettings. To change one, select the asset in the Project window; most are on its Basics tab, the rest under Advanced.

Introduction #

What Shipready does #

Shipready is a complete, crash-safe save system for Unity, with a finished save and load menu included. A beginner can set it up in minutes. When a save breaks, Shipready shows the developer why and gets the player back into their game.

What you get:

  • Saving with one line of code, or by ticking the values you want saved in the Inspector.
  • Slots, autosaves and a quicksave, plus one global file for player settings that loading a slot never overwrites.
  • World persistence. Objects in your scenes remember their position, active state, destruction, physics and the fields you tick. Objects spawned at runtime come back, and so do links between objects and to assets such as item definitions. Scenes the player has left keep their state.
  • Crash-safe writes and automatic recovery. Every save is written to a temporary file, checked, then swapped into place. Rotating backups are kept, and a damaged save falls back to the newest good backup.
  • Saves you can see. A Save Inspector opens any save as a searchable tree, and Diagnostics explains in plain English what would stop saving from working.
  • Planned game updates. Numbered migration steps keep old saves loading after you change your game.
  • A finished player menu with thumbnails, badges, confirmations, mouse, keyboard, gamepad and touch.
  • Readable saves by default, with optional compression and encryption.
  • Host-only co-op hooks, with a Netcode for GameObjects sample.
  • No exceptions into your game. Every call returns a result with an error code, a plain-English message and a link to its entry in Troubleshooting.md.

What Shipready does not do #

  • It does not save any object automatically. It saves plain values and the Unity state described in this Guide and the Reference. Anything else needs a short script.
  • It is not anti-cheat. Encryption stops casual save editing, not a determined player.
  • It has no cloud sync in 1.0. A Steam Cloud setup guide is included instead.
  • It does not load a save in the middle of a co-op session. The host loads before friends join.
  • Some engine state is not captured: particle systems, physics joints, running coroutines, and the exact path of a NavMesh agent (it walks to its saved destination again). The Animator, Audio Source, Enabled and NavMesh Agent savers cover the common cases with no code; see The built-in savers.

LimitsAndFAQ.md lists every limit in detail, with answers to common questions.

Unity versions and platforms #

Supported in 1.0
Unity Supported from 2022.3 LTS, the minimum version. Tested on 6.3 LTS and the newest Unity 6 release. Other versions, including 2022.3 and 6.0 LTS, are supported but not tested separately.
Platforms Windows 10 and 11, 64-bit. macOS, iOS, Android, Linux, WebGL and consoles are not supported in 1.0.
Scripting backends Mono and IL2CPP
Render pipelines Built-in, URP and HDRP. The core has no rendering code. Demos are checked in Built-in and URP; HDRP gets automated tests only.

The co-op sample needs Unity 6 and Netcode for GameObjects 2.x. See LimitsAndFAQ.md for the full platform list.

Getting started #

QuickStart.md takes you from import to a working save and load in about ten minutes, with screenshots. This section is the short version.

Required Unity packages #

The save menu, the editor tools' windows (the Start window, the Setup Wizard, the Save Inspector and Diagnostics) and the demos are built on Unity UI (com.unity.ugui) and TextMesh Pro, which is part of Unity UI from Unity 2023.2 and the separate com.unity.textmeshpro package in Unity 2022.3. Projects made from Unity's templates already have both. The Asset Store installs them together with Shipready when the publisher declares them as dependencies; otherwise install them in the Package Manager, as below.

If a project lacks one of them, the import still finishes without compile errors. The runtime (RareGeometry.Shipready.Save, so SaveKit and everything your game code calls) and the core editor services (RareGeometry.Shipready.Save.Editor.Core: saved ids for Saveables, the registries and their Registries commands, and the migration link file for builds) compile and keep working. The save menu, the editor tools' windows and the demos wait for the package. The small RareGeometry.Shipready.Save.Editor.Setup assembly then logs a warning once per editor session that says which package is missing and how to install it, and adds Tools → Shipready → Saves → Required Packages, which shows the same explanation. Its Open Package Manager button only opens Unity's Package Manager on that package; Shipready never installs, updates or removes a package itself. In the Package Manager, choose Unity Registry, select the package and click Install. Until the package is in, a player build stops with the same message, because the menu and the demos would be missing from it. Once Unity has compiled the rest of Shipready, the Start window opens as usual and the Required Packages command goes away. Troubleshooting has the same steps in short.

The Start window and the Setup Wizard #

The Start window opens by itself the first time Shipready is imported into a project that has no settings asset, and at any time from Tools → Shipready → Saves → Start. It offers four choices:

  • Make objects remember their state: select objects in the Hierarchy and click one button; each gets a Saveable, with the fields that look like state already ticked.
  • Add a save/load menu: choose where the F5 / F9 test hotkeys work and add the menu to the open scene.
  • Save values from my scripts: two lines of code to copy.
  • Make it yours: opens the Menu Style window, to give the menu your game's look, layout and words (Make it yours).

Its status strip checks the five things a first save needs, each with a one-click fix: Settings found (Create), Scene saved (Save scene), Scene in Build Settings (Add), Hotkeys on (Add, or Turn on) and Menu text ready (Import, which adds TextMesh Pro's essential resources; the menu and the demos show no text without them). Every fix except Import is one Undo step.

The Setup Wizard (Tools → Shipready → Saves → Setup Wizard) has two steps: Where saves go (the save folder, file names and, folded away, slots and autosave) and Menu and hotkeys. The first step starts with What kind of game is it?: Story / RPG (20 slots, a quicksave, autosave on every new scene and on quit, pictures), Roguelike (one slot, autosave on quit), Arcade / mobile (one slot, autosave only, small packed files) or Custom (as it is). Each preset lists exactly what it would change, and warns when saves in higher slots would stop showing, before you click Use these settings. Presets never change the passphrase, the save folder or the file names. The same row is on the settings asset's Basics tab, where it applies at once as one Undo step. Each step has Apply and continue and Skip, and each Apply is one Undo step. The last page lists everything it created or changed. Everything else (categories, packing, encryption and backups, game updates, world objects and the scene scan) is on the settings asset's Advanced tab. See Editor tools for each in detail.

Starting Shipready in your game #

Shipready starts by itself. Initialise Automatically is on by default; on the settings asset's Basics tab, and in the wizard under Slots and autosave, it is Start Shipready by itself. With it on, Shipready starts when the game runs, just before the first scene loads, using the settings asset ShipreadySaveSettings from its Resources folder. This happens in the Editor and in builds, in every Play session, also with domain reload switched off. You need no code: the save menu, the Saveable components and your own scripts can save and load from the first frame, and SaveKit.IsInitialised is already true when Awake runs in your first scene.

Starting does three things:

  • It loads the settings asset and checks it.
  • It loads the global file, if there is one, so the player's settings are in place before anything reads them. A global file that cannot be read does not stop Shipready: it starts anyway, with a warning in the Console.
  • It finds your migration steps, and creates one hidden object that counts playtime, runs the autosave triggers, applies scene memory as scenes load and releases restored rigidbodies.

If Shipready cannot start:

  • There is no settings asset in a Resources folder. Nothing starts. Every save and load returns NotInitialised (SK005), and the save menu shows "Saving is not available yet." with no slots. Open Tools → Shipready → Saves → Start and click Create next to No settings yet.
  • A setting cannot be used. The Console shows an error that starts "Shipready could not start by itself" and names the problem and its code, such as CategoryUnknown (SK150) or SettingsInvalid (SK153). Fix the setting and press Play again.

Starting Shipready yourself. Switch Initialise Automatically off, and call SaveKit.Initialise() yourself, when Shipready has to wait for something before it starts:

  • The save folder depends on the player. A Profile Folder with {profile} in it needs SaveKit.ProfileId before Shipready starts (see Profile folders).
  • Settings you change in code for this run. Change a copy of the asset (Instantiate(asset)) and pass it to SaveKit.Initialise(settings).
  • Storage of your own, for a platform that needs a different kind of storage: SaveKit.Initialise(settings, storage) takes your ISaveStorage.

Then start Shipready once per Play session, on the main thread, before anything saves or loads. A small script on an object in the first scene your game loads does it:

using RareGeometry.Shipready.Save;
using UnityEngine;

// Only needed with Initialise Automatically switched off.
// Put this on an object in the first scene your game loads.
public class SaveKitStartup : MonoBehaviour
{
    void Awake()
    {
        // Loading this scene again must not start Shipready twice.
        if (SaveKit.IsInitialised) return;

        SaveResult started = SaveKit.Initialise();
        if (!started.Success) Debug.LogError(started.ToString());
    }
}

SaveKit.Initialise returns a result instead of throwing. A problem with the settings fails it with the same codes as above. Calling it while Shipready is already running is allowed: Shipready simply starts again with the settings you pass, and loads the global file again.

SaveKit.Shutdown() stops Shipready. It forgets the settings, the values in memory, scene memory, event handlers and the co-op hooks, and touches nothing on disk. Each new Play session resets Shipready, also with domain reload switched off, and then starts it by itself again, or waits for your Initialise call.

Your first save #

  1. Open Tools → Shipready → Saves → Start. Click every fix the status strip offers: Create (the settings), Save scene, Add (to Build Settings) and Add (the save menu and the F5 / F9 test hotkeys). A load opens the saved scene again from its file, so a scene that was never saved cannot come back.
  2. Choose Make objects remember their state. Select an object that should remember its state, such as a chest or a door, and click Make the selected objects remember their state.
  3. Select the object. The top of its Saveable says in one sentence what it saves. To save another script value such as isOpen, tick it under Values from your scripts.
  4. Save the scene again (File → Save), so the menu and the Saveable stay in it.
  5. Press Play. Press F5 and save to slot 1. Change something, press F9 and load slot 1. A note at the top of the Game view says what was saved and what came back.
  6. Click the note, or open Tools → Shipready → Saves → Save Inspector, to see exactly what was saved.

In the Editor, a load opens a saved scene even when it is not in Build Settings, and the Console warns once (SK134) that a build could not. A scene that was never saved cannot be opened again, so its state is restored into it in place, while it is still open.

Checkpoint: each save and load shows a note in the Game view, such as "Saved Slot 1: 12 objects, 3 values", and prints a one-line report in the Console, such as [Shipready] Save slot_01.save: 12.4 ms, 5 categories, .... If something did not come back, read the warnings in the Console and in the Save Inspector's report list. Each one names the object and links to its fix.

Using Shipready from your own assemblies #

The RareGeometry.Shipready.Save and RareGeometry.Shipready.Save.UI assemblies are auto-referenced, so scripts in Unity's default assemblies can use them straight away. If your scripts sit in an assembly definition of your own, add a reference to RareGeometry.Shipready.Save, and to RareGeometry.Shipready.Save.UI if they use the menu. An editor assembly of your own that calls the registry upkeep (RegistryUpkeep, in RareGeometry.Shipready.Save.Editor.Registries) references RareGeometry.Shipready.Save.Editor.Core; the editor tools' windows are in RareGeometry.Shipready.Save.Editor.

Most game code needs only using RareGeometry.Shipready.Save;. A few types live in sub-namespaces: RareGeometry.Shipready.Save.Settings (the settings asset), RareGeometry.Shipready.Save.Diagnostics (logging and reports), RareGeometry.Shipready.Save.World (scene loaders), RareGeometry.Shipready.Save.Coop (co-op hooks) and RareGeometry.Shipready.Save.UI (the menu).

Saving plain values #

SaveKit.Data holds the plain values your game saves: gold, the current day, a volume setting, the list of unlocked levels. Values live in memory until a save writes them, and a load replaces them.

Set, Get, Has and Remove #

using RareGeometry.Shipready.Save;
using UnityEngine;

public class Wallet : MonoBehaviour
{
    int gold;

    public void Earn(int amount)
    {
        gold += amount;
        SaveKit.Data.Set("gold", gold, "Progress");
    }

    public void ReadBack()
    {
        gold = SaveKit.Data.Get("gold", 0, "Progress");   // 0 when nothing is saved yet
    }
}
  • Set(key, value, category) stores a value. Leave the category out to use the Default Category.
  • Get(key, fallback, category) reads it. The fallback is returned when there is no value, so a value added in a game update simply starts at its default in old saves.
  • Has(key, category) says whether a value is there, and Remove(key, category) removes it.
  • Keys are case-sensitive. Setting the same key again replaces the value.
SaveKit.Data.Set("gold", 250);                        // the Default Category (Progress)
bool known = SaveKit.Data.Has("gold", "Progress");
SaveKit.Data.Remove("gold", "Progress");
SaveKit.Data.Set("musicVolume", 0.8f, "Settings");    // a Global category: goes to the global file

A save takes a copy of the values as it starts, so your game can keep changing them straight away. To make sure a value is current at the moment of every save, set it from a Saving event handler (see Events).

SaveKit.Data.Clear() and ClearCategory(name) forget values in memory. They are not a new game: an empty category keeps what the file already holds when you save over it. Use SaveKit.NewGame() instead (see Starting a new game).

Saving and loading #

Slots: save and load #

Every save and load comes in a background form that you await and a blocking form that finishes before the next line runs. Slot saves and loads also come with a callback, for code that does not use await.

Call Form Use it for
SaveKit.SaveAsync(slot) Background Saving during play
SaveKit.LoadAsync(slot) Background Loading during play. In the default load mode it loads the saved scenes first.
SaveKit.SaveInBackground(slot, onComplete) Background, with a callback The same as SaveAsync, calling your method with the result (see Callbacks)
SaveKit.LoadInBackground(slot, onComplete) Background, with a callback The same as LoadAsync, calling your method with the result
SaveKit.Save(slot) Blocking Saving when the game is about to quit
SaveKit.Load(slot) Blocking Loading into the scenes that are open now 
using RareGeometry.Shipready.Save;
using UnityEngine;

public class SaveButtons : MonoBehaviour
{
    public async void SaveSlot(int slot)
    {
        SaveResult saved = await SaveKit.SaveAsync(slot);
        if (!saved.Success) Debug.LogWarning(saved.ToString());
    }

    public async void LoadSlot(int slot)
    {
        LoadResult loaded = await SaveKit.LoadAsync(slot);   // loads the saved scenes, then restores state
        if (!loaded.Success) Debug.LogWarning(loaded.ToString());
    }
}

Slots count from 1. A slot outside 1 to Slot Count returns SlotOutOfRange (SK151); loading an empty slot returns SlotEmpty (SK152).

What a save does: it captures the world into SaveKit.Data, copies the categories it saves, and hands the copy to a background thread. There the file already on disk is read and brought up to date, the categories being saved replace the ones in it, and the result is packed, written, verified and swapped into place. When the game holds any Global values, a full slot save also writes the global file; a save that names only Slot categories leaves it alone.

What a load does: it reads, verifies, unpacks and migrates the file on a background thread, then puts the values into SaveKit.Data on the main thread, restores the world and takes the slot name, location, summary lines and playtime from the file. Global categories are never touched by a slot load. A Slot category the file does not hold goes back to empty, so two playthroughs never mix.

While LoadAsync is still loading the scenes of its save, slot saves, autosaves, quicksaves and backup restores return LoadInProgress (SK154) and write nothing. Saving the global file stays allowed.

In the default load mode, LoadAsync replaces the loaded scenes. A script in one of those scenes is destroyed during the await. Code after the await still runs, but should not touch the destroyed object. Keep such code on an object that survives, for example under DontDestroyOnLoad.

Partial saves and loads #

Every save and load takes an optional list of categories. A checkpoint can save only Progress and World and leave Inventory and Quests in the file exactly as they were:

SaveResult checkpoint = await SaveKit.SaveAsync(1, new[] { "Progress", "World" });
LoadResult progressOnly = SaveKit.Load(1, new[] { "Progress" });
  • Leaving the list out, or passing null, means every category.
  • Every save is a merge: a category that holds no values in memory also keeps what the file holds.
  • A save that has to keep categories from the file fails, and leaves the file untouched, when that file cannot be read, comes from a newer version or cannot be migrated.
  • World objects are captured and restored only when their category is in the list.

The global file #

Shipready loads the global file when it starts. Save it on its own when the player changes a setting:

SaveKit.Data.Set("musicVolume", 0.8f, "Settings");
SaveResult saved = SaveKit.SaveGlobal();          // or await SaveKit.SaveGlobalAsync()

SaveKit.LoadGlobal() and LoadGlobalAsync() take the settings back to what was last saved. A game with no global file yet gets FileNotFound (SK100). The global file always falls back to its newest good backup when it is damaged, whatever Automatic Fallback says, because there is no slot card to restore it from. In co-op, every player keeps their own global file.

The global file is written with File Options, like the slots, unless you give it options and an extension of its own, for example to keep it out of Steam Cloud (see The global file's own options).

Autosaves #

Trigger Setting Default When it fires
Quit Autosave On Quit on When the game closes, and on mobile platforms when the game is paused or suspended. On a desktop, switching to another window does not autosave.
Timer Autosave On Timer, Autosave Interval Seconds off, 300 Every interval, counted in unscaled time, so setting Time.timeScale to 0 does not stop it
Scene change Autosave On Scene Change off Each time the active scene changes
  • The quit autosave uses the blocking path, so the operating system cannot cut it short. Timed and scene-change autosaves run in the background.
  • Each autosave overwrites the oldest of the Autosave File Count files. The menu lists autosaves in Load mode, newest first.
  • The timer starts again after every autosave and after every successful load, so the game never autosaves a moment after the player loaded.
  • No autosave is written while a load is still loading its scenes, and a co-op client saves only its own global file on quit.
  • Every autosave and quicksave gets a thumbnail rendered from the main camera while Capture Autosave Thumbnails is on. The camera is rendered and read back on the main thread, after the Saving event and before the save gathers its values (about 2 ms on the benchmark machine; see Measured benchmarks); the PNG is made on the save's background thread.

To autosave from code, call SaveKit.Autosave() or await SaveKit.AutosaveAsync(). To hold autosaves back, during a cutscene or a boss fight for example, switch the scheduler off:

if (SaveKit.Autosaves != null) SaveKit.Autosaves.Enabled = false;   // all triggers, including quit
SaveKit.Playtime.IsPaused = true;                                    // optional: stop the playtime clock too

SaveKit.Autosaves is null until Shipready has started. SaveKit.LoadNewestAutosave() loads the newest autosave (for a Continue button that also counts the slots and the quicksave, use LoadMostRecent), and await SaveKit.LoadNewestAutosaveAsync() does the same in the background. Both return FileNotFound (SK100) while there is no autosave yet.

The quicksave #

Switch on Quicksave Enabled (the wizard's Quicksave slot), then:

SaveResult quick = SaveKit.Quicksave();     // InvalidArgument (SK002) while the quicksave is switched off
LoadResult back = SaveKit.LoadQuicksave();

Both are blocking calls. await SaveKit.QuicksaveAsync() and await SaveKit.LoadQuicksaveAsync() do the same in the background, like SaveAsync and LoadAsync. The menu lists the quicksave in Load mode once one exists.

Starting a new game #

Call SaveKit.NewGame() when the player starts a new game. Shipready resets its own data; your game resets its own objects. NewGame works in memory only, and nothing on disk changes:

  • every Slot category becomes empty, so the next save replaces those categories in the file instead of keeping an old slot's;
  • scene memory, destroyed lists, spawned objects and per-player data are forgotten;
  • the slot name, location, summary lines, playtime and the autosave timer start again;
  • Global categories, such as the player's settings, are kept.

NewGame does not touch the objects in the scenes that are open: they keep whatever state they have. Then do one of these:

  • Load the first scene of the new game. Its objects start from their scene defaults:
SaveKit.NewGame();
SaveKit.LoadScene("Level1");
  • Or start the new game in the scene that is already open. Put its objects, and your own values, back to their new-game state yourself, for example in the same method that calls NewGame. The next slot save or quicksave captures the open scene as it is then. Objects the old game destroyed are gone from the open scene, so reloading the scene is often the simplest reset.

The scenes that are open when you call NewGame are marked, so that leaving them through SaveKit.LoadScene or SaveKit.UnloadScene, or SaveKit.World.CaptureScene before an unload of your own, does not put the old game back into scene memory. What happens to a marked scene depends on the save:

  • Saves made by the player or your code capture every loaded scene and clear the mark of each marked scene they capture, because from then on its state belongs to the new game. These are slot saves (Save, SaveAsync and SaveInBackground), quicksaves, and your own SaveKit.Autosave() or AutosaveAsync() calls.
  • Shipready's own autosaves, on the timer, on a scene change and on quit or pause, do not capture a scene that is still marked, and leave its mark in place. So an autosave made before the player saves the new game can never write the old game's objects into the new game's save.

So when a new game starts in the open scene, make a slot save or a quicksave before the player leaves it, or its changes since NewGame are not remembered when they come back.

Continue, copy, rename and reset progress #

A title screen, an options screen and a pause menu need a few more calls. Each one returns a result like any save or load.

Call What it does
SaveKit.LoadMostRecent() and LoadMostRecentAsync() Loads the newest save of every kind: a slot, an autosave or the quicksave, by its save time. Saves that cannot be loaded (damaged with no valid backup, or from a newer version of the game) are passed over. This is what a Continue button does.
SaveKit.HasAnySave Whether there is anything to continue from. Grey Continue out while it is false.
SaveKit.GetMostRecentSaveInfo() The slot info of that newest save, to show on the button ("Continue: Old Mill, 2 h 10 min"). Null when there is none.
SaveKit.CopySlot(from, to) Copies a slot, or an autosave or the quicksave through its slot info, into a slot, with its picture. The copy is the same save: data, name, playtime and save time. What the target held is replaced and kept as its newest backup.
SaveKit.RenameSlot(slot, name) Gives a saved slot a new name without changing anything else; the save time stays. Blank goes back to "Slot 2". Names are trimmed and cut to 64 characters. When the game is playing that save, its next save keeps the new name.
SaveKit.DeleteAllSaves(includeGlobal) Deletes every slot, autosave and the quicksave, each with its backups and picture: "reset progress". The global file with the player's settings stays unless you pass true. The values in memory stay as they are; call NewGame() afterwards to start afresh.

Playtime stops while it is paused, and the save menu and the Game Menu pause it while they are open, so time on a title screen or in a pause menu does not count.
SaveKit.TimeSinceLastSave How long the game has run since the last save, load or new game, in real time.
SaveKit.KindOf(fileName) Whether a file named in an event is a slot, an autosave, the quicksave or the global file. 
continueButton.interactable = SaveKit.HasAnySave;

void OnContinue()  { SaveKit.LoadMostRecentAsync(); }
void OnQuit()      { if (SaveKit.HasUnsavedProgress) AskFirst(); else Application.Quit(); }

The Game Menu does all of this with no code.

No code: Save Actions, Save Events and Save Point #

Three components put saving into the Inspector, for UI buttons, triggers and sounds.

  • Save Actions (Add Component > Shipready > Save Actions): pick one of its methods in a Button's On Click list, or any UnityEvent: Save To Slot, Load Slot, Quicksave, Quickload, Autosave, Continue, New Game, Delete Slot or Delete All Saves. The slot number goes in the box beside the method. Each runs in the background and then raises On Succeeded or On Failed (with the reason). Set New Game Scene to load your first level, and Continue Scene when your title screen is in another scene than the game. Nothing here asks the player first; the save menu and the Game Menu ask.
  • Save Events (the SaveEventListener component): Shipready's events as UnityEvents: On Saving, On Saved, On Save Failed, On Loading, On Loaded, On Load Failed and On Recovered From Backup. Drag an AudioSource or an Animator in for a sound or an effect. Tick which saves count: slots, autosaves, the quicksave and the global file (off by default, so storing a setting plays no "Game saved" sound).
  • Save Point: a checkpoint. Put it on an object with a trigger collider (3D or 2D) and tag the player Player. Walking in writes the next autosave, or a slot or the quicksave you pick, with a Cooldown (10 seconds by default) and an Only Once option. Location Name is what the slot card shows ("Old Mill"). Call Save Now from any UnityEvent to save at the end of a cutscene or a dialogue choice. Whether an only-once point has fired is not saved: add a Saveable with an Enabled Saver, or switch the point off from its On Saved.

Events #

SaveEvents has five events. Each handler receives a SaveEventInfo with the operation, the slot number (0 for the global file, an autosave or the quicksave), the file name, the result code, the report and, for a load, which copy of the file was read.

Event When
Saving A save is starting, before anything is gathered. Values you put into SaveKit.Data here are part of the save.
Saved A save has finished, successfully or not
Loading A load is starting, before the file is read
Loaded A load has finished, successfully or not. In the default load mode it fires once every saved scene is loaded and restored.
RecoveredFromBackup A load had to use a backup. Loaded fires as well. 
using RareGeometry.Shipready.Save;
using UnityEngine;

public class PlayerStats : MonoBehaviour
{
    int gold;

    void OnEnable()
    {
        SaveEvents.Saving += OnSaving;
        SaveEvents.Loaded += OnLoaded;
        SaveEvents.RecoveredFromBackup += OnRecovered;
    }

    void OnDisable()
    {
        SaveEvents.Saving -= OnSaving;
        SaveEvents.Loaded -= OnLoaded;
        SaveEvents.RecoveredFromBackup -= OnRecovered;
    }

    // Before the save gathers anything: put the latest values in.
    void OnSaving(SaveEventInfo info)
    {
        SaveKit.Data.Set("gold", gold, "Progress");
    }

    // After a load: take the values back out.
    void OnLoaded(SaveEventInfo info)
    {
        if (info.Success) gold = SaveKit.Data.Get("gold", 0, "Progress");
    }

    void OnRecovered(SaveEventInfo info)
    {
        Debug.Log("A backup was used: " + info.LoadedFrom);
    }
}
  • Handlers run on the main thread, so they can touch Unity objects, show a saving icon or pause the game.
  • A handler that throws is reported in the Console; the other handlers still run and the save is not affected.
  • Do not start another save of the same file from a handler.
  • SaveKit.Shutdown() removes every handler, and so does the start of every Play session.

Results #

Every call returns a result instead of throwing. Saves, deletes and restores return a SaveResult; loads return a LoadResult.

Member What it tells you
Success Whether you got what you asked for. A load rescued from a backup counts as a success.
Code A SaveErrorCode, such as FileDamaged or HostOnly. Each has a stable SK number.
Message One plain-English sentence, with details such as the file name in brackets
DocumentationLink The entry in Troubleshooting.md, for example RareGeometry/Shipready/Save/Documentation/Troubleshooting.md#sk101
Report Counts, timings, bytes and warnings (see Logging and reports)
LoadedFrom (loads) Which copy was read: Main, Temporary, Backup1, Backup2 or OlderBackup
RecoveredFromBackup (loads) Whether the data came from a backup or a leftover temporary file
SavedUtc (loads) When the copy that was loaded was saved, so you can say "Restored from backup (date)"

ToString() puts the code, message and link on one line, ready for a log.

using System.Threading.Tasks;
using RareGeometry.Shipready.Save;
using RareGeometry.Shipready.Save.Diagnostics;
using UnityEngine;

public class LoadWithFeedback : MonoBehaviour
{
    public async Task LoadSlot(int slot)
    {
        LoadResult loaded = await SaveKit.LoadAsync(slot);
        if (!loaded.Success)
        {
            Debug.LogWarning(loaded.ToString());          // for example: SK120 ... See .../Troubleshooting.md#sk120
            return;
        }

        if (loaded.RecoveredFromBackup)
        {
            Debug.Log("Restored from backup (" + loaded.SavedUtc.ToLocalTime() + ")");
        }

        foreach (SaveWarning warning in loaded.Report.Warnings) Debug.LogWarning(warning.ToString());
    }
}

A successful call can still carry warnings, for example an object in the save that no longer exists in the scene. Each warning has its own code.

Blocking or background: the one rule #

Every call that ends in Async finishes back on the main thread, so the code after an await can touch Unity objects. That also means the main thread must stay free to get there.

Never call .Wait() or read .Result on one of these tasks from the main thread. The task is waiting for the main thread, so the game would freeze. When a save must be finished before the next line runs, such as when the game quits, use the blocking SaveKit.Save or SaveKit.Load. They are built for exactly that.

In a coroutine, wait for a task without blocking:

Task<SaveResult> saving = SaveKit.SaveAsync(1);
yield return new WaitUntil(() => saving.IsCompleted);

Or use the callback forms below, which need neither await nor a coroutine.

Callbacks instead of await #

SaveKit.SaveInBackground and SaveKit.LoadInBackground do the same work as SaveAsync and LoadAsync, and call a method of yours with the result when they have finished:

using RareGeometry.Shipready.Save;
using UnityEngine;

public class SaveButtonsWithCallbacks : MonoBehaviour
{
    public void SaveSlot(int slot)
    {
        SaveKit.SaveInBackground(slot, result =>
        {
            if (!result.Success) Debug.LogWarning(result.ToString());
        });
    }

    public void LoadSlot(int slot)
    {
        SaveKit.LoadInBackground(slot, OnLoaded);
    }

    void OnLoaded(LoadResult result)
    {
        if (!result.Success) Debug.LogWarning(result.ToString());
    }
}
  • The callback runs on the main thread, so it can touch Unity objects. LoadInBackground calls back when LoadAsync would finish: in the default load mode, once the saved scenes are loaded and restored.
  • A call that is refused straight away, such as a slot out of range or an empty slot, calls back before SaveInBackground or LoadInBackground returns.
  • An exception in your callback is caught and written to the Console. It never reaches Shipready or the rest of your game.
  • Both take the same optional list of categories as SaveAsync and LoadAsync, as a third argument. Pass null as the callback to save or load without being told.
  • The rule about loads that replace the scenes applies here too: a callback on an object in one of those scenes runs after its object is destroyed.

Slots and slot info #

Listing slots #

using System.Collections.Generic;
using RareGeometry.Shipready.Save;
using UnityEngine;

public class SlotList : MonoBehaviour
{
    readonly List<SlotInfo> slots = new List<SlotInfo>();

    public void Show()
    {
        SaveKit.GetSlotInfos(slots);    // one entry per slot, empty slots included
        foreach (SlotInfo info in slots)
        {
            if (!info.Exists)
            {
                Debug.Log("Slot " + info.SlotNumber + ": empty");
                continue;
            }
            Debug.Log(info.Name + ", " + info.Location + ", saved " + info.SavedUtc.ToLocalTime()
                      + ", played " + PlaytimeTracker.Format(info.PlaytimeSeconds)
                      + (info.IsDamaged ? " (damaged)" : string.Empty));
        }
    }
}
  • GetSlotInfo(slot) reads one slot. It never returns null: an empty, out-of-range or damaged slot comes back as an info the menu can draw.
  • GetAutosaveInfos(list) lists the autosaves, newest first, and GetQuicksaveInfo() the quicksave.
  • HasSave(slot) says whether a slot holds anything to load.
  • Load(info), LoadAsync(info), Delete(info) and RestoreBackup(info) work on any of these infos, so one menu can treat slots, autosaves and the quicksave alike.

Reading slot info never moves or changes a file. A compressed or encrypted save is fully checked when its info is read, so a damaged one shows as damaged before the player tries to load it. The result is cached in slots.index until the file changes.

Thumbnails #

The save menu takes a thumbnail by itself, just before the Save menu opens, from its Camera for the picture (empty: main camera) (ThumbnailCamera) or from Camera.main. Without a camera there is simply no thumbnail.

To set one from code, call SaveKit.SetNextThumbnail(texture) before you save. The picture is scaled down to 320×180 and copied straight away, so you can destroy your texture at once. The next successful slot save, autosave or quicksave stores it beside its file as <save file>.thumb.png, after the save itself is safely in place, and then forgets it. A picture that cannot be used or written is a warning in that save's report, never a failed save.

using System.Collections;
using System.Threading.Tasks;
using RareGeometry.Shipready.Save;
using UnityEngine;

public class SaveWithPicture : MonoBehaviour
{
    public IEnumerator SaveSlot(int slot)
    {
        yield return new WaitForEndOfFrame();
        Texture2D shot = ScreenCapture.CaptureScreenshotAsTexture();
        SaveKit.SetNextThumbnail(shot);   // scaled to 320×180 and copied straight away
        Destroy(shot);

        Task<SaveResult> saving = SaveKit.SaveAsync(slot);
        yield return new WaitUntil(() => saving.IsCompleted);
        if (!saving.Result.Success) Debug.LogWarning(saving.Result.ToString());
    }
}

To show a thumbnail in your own menu, read it with Thumbnails.Read(SaveKit.Storage, info.FileName). It returns a new texture, or null when there is none; destroy the texture when you no longer show it.

Every save takes its own picture. While Capture Autosave Thumbnails (under Autosave triggers in the settings asset) is on, which it is by default, Shipready renders a picture just before every slot save, autosave and quicksave that has none set with SetNextThumbnail: the camera in SaveKit.ThumbnailCamera, or Camera.main when that is not set (or, when a menu or cutscene camera has turned the main camera off, the camera drawing the screen), rendered once at 320×180 and read back on the main thread; the PNG is made on the save's background thread. The picture belongs to that one save: if the save fails, it is dropped, and it never carries over to a later save. Screen-space overlay UI is not drawn by cameras, so the HUD and the menu never appear in it. There is no picture without a camera or a graphics device (a server or a -nographics run), and none for the autosave of a phone or handheld being suspended, when the game may no longer draw. The save menu takes its own picture before every save it makes, while its Take a picture for each save (CaptureThumbnail) is on and there is a camera.

SaveKit.ThumbnailCamera = overviewCamera;   // optional: the view the cards should show

A save without a picture has no thumbnail. A successful slot save, autosave or quicksave made without a picture removes the thumbnail of the save it replaced, so a card never shows a picture of an older save; it shows "No preview" instead. Slot saves from your own code have a picture only when you set one. ThumbnailCapture.Capture(camera) (namespace RareGeometry.Shipready.Save) renders a camera into a picture of the right size, and is what the menu and the autosaves use:

Texture2D shot = ThumbnailCapture.Capture(Camera.main);   // null when there is no camera
if (shot != null)
{
    SaveKit.SetNextThumbnail(shot);
    Destroy(shot);
}
SaveKit.Save(slot);

Thumbnails are plain PNG files and are never encrypted. They are not rotated with backups: after a backup is restored or loaded, the card shows the picture of the newer save until the slot is saved again.

Deleting and restoring backups #

  • SaveKit.Delete(slot) deletes the save, its temporary file, its backups and its thumbnail. Damaged copies kept for support (.corrupt-<time>) stay.
  • SaveKit.RestoreBackup(slot), or RestoreBackupAsync(slot), puts the newest valid backup of a damaged slot back in place through the crash-safe write. The damaged file is kept as .corrupt-<time> and the backups stay where they are. It returns RecoveredFromBackup (SK102) on success, which counts as a success, and FileDamaged (SK101) when no backup is valid, with nothing changed. A main file that reads correctly is never replaced.

The menu offers Restore backup when Automatic Fallback is off; with it on, a damaged slot simply loads from its backup. See Reliability and recovery.

World persistence #

The Saveable component #

Add Add Component → Shipready → Saveable to any GameObject that should remember its state. Each Saveable is saved under a permanent id:

Object Its id
Placed in a scene A GUID given in the Editor when the Saveable is added and saved with the scene. A duplicated object gets a new id automatically; the original keeps its own.
A prefab asset None. The prefab carries a prefab id instead: its asset GUID.
Spawned at runtime A new GUID when it wakes up, saved with its prefab id
A Saveable on a child of a spawned prefab The root's id plus an id that is fixed inside the prefab; saved with the root

If an object in the save no longer exists in the scene, for example because you deleted it in an update, it is skipped and listed in the report as ObjectNotFound (SK130); the load still succeeds. An object new to the scene keeps its scene defaults.

Category. A Saveable is saved in the World Category unless you pick another one in its Category field. A save of only some categories leaves it alone unless its category is one of them.

The built-in savers #

Saver Default What it saves and restores

Destroyed objects. A Saveable records its destruction only during gameplay. Unloading a scene, quitting the game, and objects Shipready itself removes during a load record nothing. Each scene keeps its own destroyed list.

The Field Picker #

The Field Picker sits at the bottom of the Saveable inspector. It lists, per component on the same GameObject, every field Unity itself saves: public fields and fields marked [SerializeField], including those declared in base classes. Tick a field and its value is saved and restored. Fields that cannot be saved are greyed out, with the reason shown.

Field type Can be ticked
Numbers, string, char, bool Yes
Enums Yes, saved by name
Vector2 to Vector4, Vector2Int, Vector3Int, Quaternion, Color, Color32, Rect, RectInt, Bounds, BoundsInt Yes
A class or struct marked [Serializable] Yes, under Unity's own rules
A link to an object that has a Saveable (the Saveable, its GameObject, its Transform or any of its components) Yes, see References
A link to an asset in the Asset Registry or the Prefab Registry, such as a ScriptableObject or a prefab Yes
List<T> or T[] of any of the above Yes
A link to a scene object without a Saveable Greyed: "points at an object that is not saved". Add a Saveable to the target first.

Dictionaries, interfaces, delegates, nullable values, abstract types, [SerializeReference], classes not marked [Serializable], multi-dimensional arrays, lists of lists Greyed, with the reason
  • The Transform (the Position saver covers it), the Saveable itself and scripts that implement ISaveable (they save themselves) offer no fields. Fields marked [HideInInspector], static, read-only or [NonSerialized] are not listed.
  • A [Serializable] class field is filled in place on load, so a field the save does not mention keeps its current value.
  • Ticked fields are saved under <ComponentType>.<field>. Renaming the component class or the field means old saves no longer find the value, and it keeps its scene default, unless a migration step renames the key (see GameUpdates.md).
  • A ticked field that is no longer saveable, or whose component was removed, is listed under "Ticked fields that are skipped when saving" with an Untick button. Diagnostics reports it too.
  • In code, Saveable.AddField(component, "fieldName") and RemoveField tick and untick fields; FieldSaver.IsSupportedField(field, out reason) gives the same answer as the Field Picker.

Custom scripts: ISaveable #

For anything the savers and the Field Picker do not cover, such as dictionaries, properties, polymorphic data or a value that has to be worked out, implement ISaveable on a script on the same GameObject as the Saveable:

// ItemDefinition.cs
using UnityEngine;

[CreateAssetMenu(menuName = "My Game/Item Definition")]
public class ItemDefinition : ScriptableObject
{
    public string displayName;
}

// Chest.cs
using System.Collections.Generic;
using RareGeometry.Shipready.Save;
using UnityEngine;

public class Chest : MonoBehaviour, ISaveable
{
    [SerializeField] bool isOpen;
    [SerializeField] List<ItemDefinition> contents = new List<ItemDefinition>();

    public void CaptureState(SaveWriter w)
    {
        w.Write("open", isOpen);
        w.WriteAssets("contents", contents);   // stored as registered asset IDs
    }

    public void RestoreState(SaveReader r)
    {
        isOpen = r.Read("open", false);
        contents = r.ReadAssets<ItemDefinition>("contents") ?? new List<ItemDefinition>();
    }
}
  • CaptureState is called on the main thread while a save is being gathered. RestoreState is called after Unity has woken the scene and before Start, and only when the save holds data for this script.
  • Every Read takes the value to use when the save does not hold that name, so a value added in a game update keeps its default.
  • SaveWriter and SaveReader handle every supported type: Write/Read, WriteEnum/ReadEnum, WriteList/ReadList/ReadArray, WriteDictionary/ReadDictionary/ReadIntDictionary (or a dictionary straight through Write and Read), WriteObject/ReadObject for nested groups, WriteAsset/ReadAsset and WriteAssets/ReadAssets for links to registered assets, and WriteObjectLink/ReadObjectLink and WriteObjectLinks/ReadObjectLinks for links to other saved objects.
  • An asset written with WriteAsset or WriteAssets that is not in the Asset Registry or the Prefab Registry is stored as an empty entry and reported in the Console as AssetNotRegistered (SK132). Register the assets you write this way (see The registries).
  • The script's data is stored under custom/<ClassName> in the object's entry. A second script of the same class on the GameObject is stored as <ClassName>[1].
  • An exception in CaptureState or RestoreState becomes a warning in the report and never stops the save or load.

Links to other saved objects. WriteObjectLink stores a link the way a ticked link field does: to a Saveable, its GameObject or any of its components, by the object's id, or to an asset in the Asset Registry or the Prefab Registry. ReadObjectLink hands the object to a method of yours, usually one that sets a field:

// Door is one of your own scripts, on an object that has a Saveable.
using RareGeometry.Shipready.Save;
using UnityEngine;

public class Lever : MonoBehaviour, ISaveable
{
    [SerializeField] bool pulled;
    [SerializeField] Door door;

    public void CaptureState(SaveWriter w)
    {
        w.Write("pulled", pulled);
        w.WriteObjectLink("door", door);
    }

    public void RestoreState(SaveReader r)
    {
        pulled = r.Read("pulled", false);
        r.ReadObjectLink<Door>("door", d => door = d);
    }
}
  • During a load, Shipready calls your method in the second pass of the restore, once every object of the load exists, including runtime objects it re-creates later in the same load, and still before Start. A link into a saved scene that has not loaded yet waits until every saved scene is in.
  • A link to an object that no longer exists, or that has no component of the type you ask for, gives null, with an ObjectNotFound warning (SK130) naming the object and the value. When the save does not hold the name at all, your method is not called, so the field keeps its default.
  • A target without a Saveable, or an asset in neither registry, is saved as an empty link, with a warning in the save's report.
  • WriteObjectLinks(name, list) and ReadObjectLinks<T>(name, list => field = list) do the same for a list. An entry whose object is gone becomes null, so the list keeps its length.

Objects spawned at runtime #

Put a Saveable on the root of a prefab. The Editor stamps the prefab id and adds the prefab to the Prefab Registry automatically whenever the prefab is imported or saved. From then on, a normal Instantiate is tracked: the copy gets a runtime id as it wakes up and is saved, with its prefab id, in the scene it is in.

On load, Shipready re-creates each saved runtime object from its prefab, gives it its saved id, applies its state, and then sets its parent and position in a second pass. When a load restores into a scene that is already open, the runtime objects already there are removed first and replaced by the saved ones.

  • Saveables on children of the prefab are saved with the root and come back with it.
  • A runtime object made from something that is not a registered prefab, such as a copy of a plain scene object, cannot be re-created. It is left out of the save with a PrefabNotRegistered warning (SK131).
  • A saved runtime object whose prefab is missing from the registry is skipped on load with the same code.

Pools. An object waiting in a pool should not be saved. Tell Shipready when your pool takes an object back and hands it out again:

using System.Collections.Generic;
using RareGeometry.Shipready.Save;
using UnityEngine;

public class CratePool : MonoBehaviour
{
    [SerializeField] GameObject cratePrefab;
    readonly Stack<GameObject> waiting = new Stack<GameObject>();

    public GameObject Take(Vector3 position)
    {
        GameObject crate = waiting.Count > 0 ? waiting.Pop() : Instantiate(cratePrefab);
        crate.transform.position = position;
        crate.SetActive(true);
        SaveKit.World.Spawned(crate);     // saved again from now on
        return crate;
    }

    public void Return(GameObject crate)
    {
        SaveKit.World.Despawned(crate);   // not saved while it waits
        crate.SetActive(false);
        waiting.Push(crate);
    }
}

Spawn hooks. By default Shipready re-creates objects with Instantiate and removes them with Destroy. To make them through a pool, a network library or Addressables instead, implement ISpawnHandler (namespace RareGeometry.Shipready.Save.Coop):

using RareGeometry.Shipready.Save.Coop;
using UnityEngine;

public sealed class MySpawnHandler : ISpawnHandler
{
    public GameObject Spawn(GameObject prefab, Vector3 position, Quaternion rotation, Transform parent)
    {
        // Make the object your way: from a pool, through the network library, from Addressables.
        return Object.Instantiate(prefab, position, rotation, parent);
    }

    public void Despawn(GameObject instance)
    {
        Object.Destroy(instance);
    }
}

Set it after Shipready has started, with SaveKit.SpawnHandler = new MySpawnHandler();. Shipready gives the new object its saved id itself, straight after Spawn returns, and sets the saved position and rotation afterwards. A hook that returns null skips that object with a warning. SaveKit.Shutdown() clears the hook.

References between objects and to assets #

A ticked field can link to:

  • another saved object: a field typed as Saveable, GameObject, Transform or any component, pointing at an object with a Saveable. A link to a GameObject is saved as { "obj": "<id>" }. A link to a component also stores the component's full type name, as { "obj": "<id>", "t": "<component type>" }, plus "c", its position among the components of exactly that type, when it is not the first. A link without "t" loads too: the component is then found by the field's type;
  • an asset: a ScriptableObject, a prefab or another asset listed in the Asset Registry or the Prefab Registry. It is saved as { "asset": "<asset id>" };
  • lists and arrays of either.

Links are restored in a second pass, once every object of the load exists. A link to an object that no longer exists becomes null, with an ObjectNotFound warning naming the field; in a list, the entry becomes null and the list keeps its length. A link to an object in another scene comes back when that object is awake, or when its scene is part of the same load.

Asset ids are the asset's Unity GUID, so you can rename or move an asset without breaking saves. A ticked link to an asset that is in neither registry is not saved, with an AssetNotRegistered warning; Diagnostics registers such assets in one click.

An ISaveable writes the same links with WriteObjectLink and reads them back with ReadObjectLink, restored in the same second pass (see Custom scripts).

Scene memory #

Scene memory keeps the state of scenes the player has left, and restores it when they come back.

  • Leaving a scene. SaveKit.LoadScene and SaveKit.UnloadScene capture a scene's state before it unloads.
  • Coming back. When a scene loads during play, its remembered state is applied automatically, after Awake and before Start. This works however the scene was loaded.
  • Saving. A save includes the remembered state of every scene, loaded or not, so the player can save in scene B and still find scene A as they left it after a load.
using RareGeometry.Shipready.Save;
using UnityEngine.SceneManagement;

public static class Travel
{
    public static void GoToCellar()
    {
        SaveKit.LoadScene("Cellar");                                       // captures the scenes it replaces
    }

    public static void OpenAttic()
    {
        SaveKit.LoadScene("Assets/Levels/Attic.unity", LoadSceneMode.Additive);
    }

    public static void CloseAttic()
    {
        SaveKit.UnloadScene(SceneManager.GetSceneByName("Attic"));         // captures, then unloads
    }
}

SaveKit.LoadScene takes a scene name or path and returns the AsyncOperation, or null when the scene cannot be loaded (reported in the Console). It loads scenes that are in Build Settings, or through your scene loader when you set one.

Your own scene loading. If you unload scenes yourself, capture them first:

Scene leaving = SceneManager.GetSceneByName("Cellar");
SaveKit.World.CaptureScene(leaving);     // remember it first
SceneManager.UnloadSceneAsync(leaving);

If a scene with Saveables unloads without being captured, Shipready warns in the Console, because its changes since the last save are lost. More scene memory calls on SaveKit.World: ApplyScene(scene) applies remembered state to a loaded scene now, HasRememberedState(scene), Forget(scene) and ClearAll().

Multiple and additive scenes #

Each scene has its own section in the save, keyed by the scene's id from the Scene Registry (its asset GUID), so renaming or moving a scene never breaks a save. The world category also records which scenes were loaded, in load order, and which one was active.

When LoadAsync loads a save in the default load mode, it loads the first saved scene on its own, adds the others one after another, restores each as it loads, and then makes the saved active scene active. A saved scene that cannot be loaded, because it is not in Build Settings or not in the Scene Registry, is a warning; the other scenes still load, and its state stays in memory until it loads. A scene that takes longer than SaveKit.World.SceneLoadTimeoutSeconds (120 seconds by default) is given up on with a warning.

Load order: Awake, restore, Start #

Unity wakes a scene's objects (Awake, OnEnable) and starts them a frame later (Start). Shipready restores saved state in between, so your Start code already sees saved values. Objects re-created by a load are restored in the frame they are made, also before their Start.

The rule: set defaults in Awake or in field initialisers, never in Start. A default set in Start would overwrite the value Shipready just restored.

A full load runs in this order:

  1. Read, verify, unpack and migrate, in the background for LoadAsync.
  2. Put the categories into SaveKit.Data, and restore the DontDestroyOnLoad objects.
  3. Load the saved scenes and set the active scene (Load Saved Scenes mode with LoadAsync).
  4. For each scene: apply the destroyed list, re-create runtime objects, apply object state (active, plain fields, ISaveable), then restore parents, positions, physics and links.
  5. Fire Loaded with the report.

When a load restores into scenes that are already running, their objects have already run Start. Code that sets up visuals from a field in Start, such as a chest lid that opens when isOpen is true, should also do so in RestoreState or in a SaveEvents.Loaded handler.

The save and load menu #

Shipready ships a finished menu: one prefab with two modes, Save and Load.

Adding it #

  • With the Start window: Add a save/load menu adds the SaveMenu prefab to the open scene, an EventSystem with the right input module, and the F5 / F9 test hotkeys (in the Editor only, unless you choose otherwise). The Setup Wizard's Menu and hotkeys step does the same.
  • By hand: drag Assets/RareGeometry/Shipready/Save/UI/Prefabs/SaveMenu.prefab into your scene. It stays hidden until something opens it.

The menu's text uses TextMesh Pro. If the text does not show, import TMP's essential resources: the Import TMP Essentials button in the Start window or the wizard, or Window → TextMeshPro → Import TMP Essential Resources.

When the scene has no EventSystem as the menu opens, the menu makes one: with an InputSystemUIInputModule when the Input System is the active input handler, otherwise a StandaloneInputModule.

Open it from your own buttons:

using RareGeometry.Shipready.Save.UI;
using UnityEngine;

public class PauseMenu : MonoBehaviour
{
    [SerializeField] SaveMenu saveMenu;
    bool paused;

    public void OnSaveClicked() { saveMenu.Open(SaveMenuMode.Save); }
    public void OnLoadClicked() { saveMenu.Open(SaveMenuMode.Load); }

    void LateUpdate()
    {
        // The Escape that closed the save menu must not also close the pause menu.
        if (saveMenu.IsOpen || saveMenu.ConsumedCancelThisFrame) return;
        if (Input.GetKeyDown(KeyCode.Escape)) paused = !paused;   // or your own Input System action
    }
}

Close() closes it, and Refresh() re-reads every slot after your game saved or deleted behind the menu's back. The menu needs Shipready to have started; before that it shows "Saving is not available yet."

Make it yours #

Tools → Shipready → Saves → Menu Style (also Make it yours in the Start window) changes how the menu looks and what it says, with no Project window, prefab or code. It works on the save menu in the open scene; if there is none, its first button adds one. A live preview shows the menu with made-up saves as you change things. The preview is drawn away from your scene, so it never changes your scene or marks it as changed.

  • Start a theme from a style: Assets → Create → Shipready → Menu Theme from a Style makes a new theme asset from any of the six, in the folder you have selected.

Sounds, keys and one part on its own (on the menu's Inspector, no code): - Events: On Opened, On Closed, On Selection Moved, On Question Asked, On Saved, On Loaded, On Deleted, On Restored and On Failed. Escape then no longer backs out when another key is chosen. The gamepad's back button backs out too (CloseWithGamepad) decides whether the gamepad's East button (B, Circle) does too. - One part on its own: select a part of the menu, such as the title or a button, and on its Themed Element tick Override Colour or Override Font Size to give just that part its own.

Your own question box. To ask "Overwrite Slot 2?" with your game's own dialog, put a component that implements ISaveMenuConfirmation on it and drag it into the menu's Confirmation field. The menu calls Ask with the question and the words for yes and no; call one of the two callbacks when the player answers:

using System;
using RareGeometry.Shipready.Save.UI;
using UnityEngine;

public class MyQuestion : MonoBehaviour, ISaveMenuConfirmation
{
    Action _yes, _no;
    public bool IsOpen { get; private set; }

    public void Ask(string question, string yes, string no, bool destructive, Action confirmed, Action cancelled)
    {
        _yes = confirmed; _no = cancelled; IsOpen = true;
        // Show your panel with the question and two buttons, then call Yes() or No().
    }

    public void Yes() { IsOpen = false; _yes(); }
    public void No() { IsOpen = false; _no(); }
    public void Cancel() { if (IsOpen) No(); }
}

The same settings are on the theme asset, so code can change them too. Change your own theme, never Shipready's, and give it to the menu, which applies it at once, even while open: myTheme.Layout.Columns = 3; saveMenu.Theme = myTheme;. The six styles are in UI/Settings/Styles; assign one to the menu's Theme to use it as it is.

Translating. The words live in a Menu Text asset. The Words tab is English; for another language, save one text per language (export, translate, import into a copy, or Assets → Create → Shipready → Menu Text) and set saveMenu.Text when the player picks a language. No extra package is needed. A game that uses Unity's Localization package can take the words from a String Table instead: see Unity Localization.

  • Lines with {0} get a value put in, such as the save's name. Keep the {0}, and type a brace twice to show one.
  • Date Format is a .NET date format, such as d MMM yyyy HH:mm, applied to the local time.
  • Date Culture Name, such as de-DE or fr-FR, decides the month and day names. Empty uses English names, the same on every machine.

Further than a style. For a change the window cannot make, make a prefab variant of SaveMenu (and of SlotCard, assigned as the menu's Card Template) and edit the variant. Or build your own menu on the public API: the Own Menu demo (Samples/Demos/Scenes/OwnMenuDemo.unity, explained in Use your own menu) is a plain uGUI list that lists the slots, saves with a picture, loads and deletes, in one short script to copy. A game whose UI is built with UI Toolkit can do the same with the Own Menu (UI Toolkit) demo (Samples/Demos/Scenes/OwnMenuUIToolkitDemo.unity, explained in Your own menu in UI Toolkit): a UXML layout, a USS style sheet and one script, with Continue.

Edit your own theme and your own variants, not Shipready's prefabs and default assets. Tools → Shipready → Saves → Generators → Rebuild Menu Prefabs replaces the three kit prefabs with fresh copies; it keeps prefab variants, your scenes and the default theme and text assets.

Messages: Display as and places #

Every message Shipready shows the player can show in six ways. Pick one in the Menu Style window's Messages tab for the whole game, or on a part's own Inspector for that part alone:

Display as Shows Example
Full text the whole sentence "Game saved", "From a newer version"
Short text a word or two "Saved", "Newer"
Icon only the icon, in the text colour (on a badge, the muted text colour) a tick
Icon in its colour the icon, in its state's colour a green tick, a red cracked page
Icon and short text both a green tick and "Saved"
None nothing
  • Which parts: the saving indicator (default: icon and short text), the save notes (icon and short text), the menu's status line and co-op line (full text) and the slot card badges (full text).
  • Three levels: the theme sets it once; a kind of message can have its own everywhere (Messages tab, Each kind's icon and own display); and a part's own Inspector can choose for that part alone (Display as at the top of the Saving Indicator, Save Notes and Save Menu Inspectors, with a live preview).
  • Colours: each state has its colour in the theme: Saving and Loading, Saved and Loaded, failures, co-op, locked and other news in the Messages tab; Autosave, Damaged, Restored and From a newer version are the badge colours in the Colours tab, so a badge and its icon always match. The six styles come with colours that read well on their boxes.
  • Icons: a built-in set drawn by Shipready in one even line weight, crisp from a small badge to a 4K screen: a turning ring for saving and loading, a tick, a tray for loaded, a ring with "!" for failures, a cracked page for damaged, a clock turning back for restored, two chasing arrows for autosave, a bolt for the quicksave, an arrow up for a newer version, two people for co-op, a padlock and an "i". Swap any of them for your own sprite (white on clear takes the colour best).
  • Places: the saving indicator and the save notes each sit top left, top centre, top right, bottom left, bottom centre, bottom right, or anywhere (Custom: a point of the screen plus an offset), with a margin from the edge. The theme sets it; a part's Position can choose its own. When the place changes while it shows, the box glides there (Glide to a new place, 0.25 seconds; 0 moves it at once).
  • Exactly centred: the icon and the words are laid out by Shipready, so the block sits in the middle of its box, the icon is level with the middle of the capital letters, and everything lands on whole pixels, at any screen shape and UI scale. A test checks it to half a pixel.
  • Your own words: the short words are in the Words tab, Short words; the notes' sentences in Save notes.

Tabs, newest first, names and copies #

Four more choices, each off by default so the menu stays as simple as it ships:

  • Tabs (Menu Style > Layout > The list): the Load menu gets All, Saves and Autosaves tabs, so a long list with autosaves stays easy to read. They show only when the Load menu lists autosaves or the quicksave (both are on by default). Up from the top card reaches the tabs; left and right move along them.
  • Newest first (Menu Style > Layout > The list): the saves are listed by save time, newest at the top, in both menus; empty slots follow.
  • Players can name their saves (PlayerNamedSaves, on the Save Menu's Inspector, Names and copies): saving asks for a name in a box under the question ("Name this save", or "Overwrite Slot 2? Give the new save a name."), starting from the game's SaveKit.SlotName. Enter saves. Saved slots in the Save menu show Rename. The name becomes SaveKit.SlotName, so the game's later autosaves carry it too.
  • Players can copy a save (AllowCopy, in the same place): saved slots in the Save menu show Copy, which copies the save into the first empty slot ("Copied to Slot 3."), so a player can keep a save before a risky choice.

Every word they show is in the Words tab (Tabs, Names and copies), in the theme's colours. Your own confirmation can take names too: implement ISaveMenuNamePrompt beside ISaveMenuConfirmation; without it, the menu's own dialog asks for names.

The Game Menu: title screen and pause menu #

GameMenu.prefab (in UI/Prefabs) is a title screen or a pause menu with no code: Continue, New Game, Save Game, Load Game, Delete All Saves and Quit. Drop it into a scene and drag your save menu into its Save Menu field.

  • Continue loads the newest save of every kind, and is greyed out while there is none. Set Continue Scene when the title screen is not the game's scene.
  • New Game starts a new game (SaveKit.NewGame()) and loads New Game Scene when you set one.
  • Save Game and Load Game open the save menu. Save Game is off by default, as a title screen has nothing to save.
  • Delete All Saves (off by default) always asks first, and keeps the player's settings unless Reset Includes Settings is on.
  • Quit asks "Quit without saving? Progress since your last save will be lost." when there is unsaved progress (SaveKit.HasUnsavedProgress), then quits, or loads Quit Scene (your title screen) when you set one. New Game asks the same way. Each question can be switched off.

As a title screen it shows the game's name at the top (from Player Settings), and a line under it when you give one: both are in the Words tab (Game menu), and each has an off switch in the Layout tab (The Game Menu).

For a pause menu, untick Open On Start and set a Toggle Key, such as Escape, or call Open() from your own button. It uses the same Menu Theme and Menu Text as the save menu: every colour, size and word is in the Menu Style window, Placement puts it left, in the middle or right, each button has its own tick box, and its Events list plays your sounds.

The saving indicator #

SavingIndicator.prefab shows a small "Saving..." with a turning ring at the edge of the screen while a save runs, then "Saved" with a tick (or "Save failed") for a moment, then fades out. Players expect to see that an autosave happened. Drop it into your first scene; it stays across scene loads. The demos have one; a new game has none until you add it.

Everything about it is yours: its colours, icons and font come from the Menu Theme, its words from the Menu Text (Saving indicator, and Short words). Display as and Position sit at the top of its Inspector, with a live preview (see Messages: Display as and places); below them, whether the icon turns, which saves show it (autosaves, the quicksave and slots by default; the global file off), the least time "Saving..." shows, how long "Saved" shows, and the fade. Switch the component off to hide it. ShowSaving() and ShowFinished(true) show it for your own long work.

The save notes #

SaveNotes.prefab shows a short note when a load finished ("Loaded"), when a save came back from its backup ("Restored"), or when a save or a load did not work, for a moment at the top centre of the screen, then fades out. Saves that worked are off by default, because the indicator shows them. Drop it into your first scene beside the indicator; it stays across scene loads. Display as, Position, which news it notes, how long a note stays and the fade are on its Inspector. Show(MessageKind.Loaded) shows a note for your own news.

Co-op clients #

On a co-op client, SaveKit.CanSave and SaveKit.CanLoad are false. The menu then shows the cards without their Save, Load, Delete and Restore buttons, and a line saying "Only the host can save or load."

Visual Scripting and Localization #

Two optional parts compile only when their Unity package is in your project, so Shipready never needs either package. Add the package and they appear; remove it and they go away with nothing broken.

Visual Scripting nodes #

With Visual Scripting (com.unity.visualscripting) installed, the fuzzy finder has an Shipready group: Save To Slot, Load Slot, Delete Slot, Autosave, Quicksave, Quickload, Continue (Load Most Recent), New Game and Delete All Saves, each with Success and Message outputs to branch on; Has Save and save system State (has any save, has unsaved progress, seconds since the last save); Get Saved and Set Saved for whole numbers, numbers, true or false, text and Vector3, which are SaveKit.Data with a key and a category; and the events On Game Saved and On Game Loaded (with success, slot and whether it was an autosave).

If the nodes do not show, open Edit > Project Settings > Visual Scripting, add RareGeometry.Shipready.Save.VisualScripting to the Node Library, and press Regenerate Nodes. The action nodes wait for the save or load, as the blocking calls do; for a very large save, use the save menu or Save Actions, which save in the background.

Unity Localization #

With Localization (com.unity.localization) installed, add Localized Menu Text (Add Component > Shipready) beside your save menu and pick a String Table. Each entry's key is the name of a word, as the field is called in Menu Text: saveTitle, loadTitle, deleteQuestion, indicatorSaving and so on. LocalizedMenuText.Keys lists them all. When the table loads, and whenever the player picks another locale, every Save Menu, Game Menu and Saving Indicator under it (or in its lists) takes the words. A key the table does not have keeps the word from Fallback, or Shipready's English. Dates follow the table's locale unless the table has a dateCultureName entry. Keep {0} in the lines that have it, and leave Smart Strings off for them.

Co-op #

Shipready supports host-only co-op saving. It has no networking code of its own; three small interfaces in RareGeometry.Shipready.Save.Coop connect it to any network library.

  • The host owns the world. Set SaveKit.Authority to an ISaveAuthority that says whether this game instance may save. On a client, every slot, autosave and quicksave save, load, delete and restore returns HostOnly (SK140) without touching storage, and SaveKit.CanSave and CanLoad are false, so the menu hides those buttons.
  • Every player keeps their own settings. The global file stays available to clients.
  • Per-player data lives in the host's save under a stable player id that your game supplies, such as a Steam ID: SaveKit.Players.For(playerId) returns a SaveData for that player. SaveKit.Identity (an IPlayerIdentity) maps a network connection to that id. A rejoining player gets their data back; an unknown player starts from defaults.
  • Networked objects come back through SaveKit.SpawnHandler (an ISpawnHandler), so the host can spawn them on the network.
  • The host loads before friends join. There is no loading during a session in 1.0. The host can save at any time.
  • Shipready restores state on the host only. Your network library shows it to the clients, so every value clients must see has to be network-synced by your game.

Coop.md explains all of this in detail, with a walkthrough of the Netcode for GameObjects sample.

Steam Cloud #

Shipready works with Steam's code-free Auto-Cloud. Its file names are chosen so that one pattern uploads only the real saves:

  • Root: WinAppDataLocalLow
  • Subdirectory: <Company Name>/<Product Name>/Saves
  • Pattern: *.save

Backups, temporary files, damaged copies, thumbnails and the slot cache do not match *.save, so they stay on the player's machine as a local safety net.

  • Two Steam users on one PC. In Steamworks, end the Subdirectory with /{64BitSteamID}, which Steam fills in. In Shipready, set Profile Folder to {profile} and set SaveKit.ProfileId to the same 64-bit Steam ID before Shipready starts (see Profile folders). Steam's {64BitSteamID} only means something to Steam; Shipready's placeholder is {profile}.
  • Machine-specific settings, such as graphics quality, stay on the PC when the global file has its own extension, such as .local, which *.save does not match (see The global file's own options).

SteamCloud.md walks through every Steamworks setting, the per-user folder, keeping device-specific settings local, and testing.

Troubleshooting and support #

Every result and every Console line carries a code such as SK101. Troubleshooting.md has one entry per code: what it means, the likely cause and the fix. The link in each result goes straight to its entry, for example Troubleshooting.md#sk101.

When something does not save or load the way you expect:

  1. Check result.Success and read result.ToString().
  2. Read the warnings in the report, in the Console or in the Save Inspector's Recent saves and loads.
  3. Run Diagnostics.
  4. Open the save in the Save Inspector to see exactly what it holds.
  5. Set Log Level to Verbose and try again.

LimitsAndFAQ.md answers the most common questions, such as where the saves are and how to start a new game.
