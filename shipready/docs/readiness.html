Ship Readiness Checker

Launch Desk > Readiness. It inspects the project and says what still needs attention before release, worst first. It is a pre-launch inspection: it finds real problems early. It does not certify a game for any store.

Run it #

Choose where the game is going (Windows, Mac and Linux; Steam Deck; mobile; WebGL; console-style) and press Inspect. Each place has its own checks.

Reading a finding #

Part Meaning
Blocker Players will hit this. Fix before release
Warning Likely to hurt players, or important and unproven
Not tested A check nobody has run or recorded yet. It is never counted as passed
Info Good to know. Nothing is broken
Passed Checked and fine (shown with Show passed too)

Each finding also says how its result was established:

Evidence Meaning
Scanned Shipready read the project (settings, scenes, assets)
Ran Shipready ran it, for example the save survival run that interrupts a save at four points
Checked by hand You did the steps and recorded the result
Needs the platform Only the real device can show it; Shipready lists what to try there

Fix makes the change for you where a safe fix exists. Show selects the scene or asset.

Checks you do by hand #

Some things only a person can judge: the first launch from a fresh install, a full save, quit and reload, every screen with a controller only, text size on a small screen. Open the finding, follow the steps, and press Passed or Failed with a note. The result is kept per target in ProjectSettings/RareGeometry/ShipreadyReadiness.json together with the game version, so it travels with the project. Clear forgets it.

What is checked #

  • The project: build scenes, game name and version, icon, development build, missing scripts, Event Systems, input handling, scripting backend.
  • Menus: a front end is in the build and in the first scene, only one, its profile is sound, every screen has a place to start with a controller, every setting players can change reaches the game.
  • Saves: the setup, and a survival run (save, restart, load, then four interrupted saves that must never report success or lose the last good save).
  • Accessibility: the game look's contrast, and which Steam accessibility tags your settings cover, with the ones they cannot cover alone said plainly.
  • Playtest: the setup, what of the tester tools reaches the release build, where Player Options and the playtest settings disagree.
  • Tutorials: the setup.
  • Other Rare Geometry products in the project report their own diagnostics here.

The report #

Export report writes an HTML page to read or share and a JSON file for tools. Both say "pre-launch inspection", list every finding with its evidence, and never show an untested check as passed.

Your own checks #

Write a class that derives from ReadinessRule anywhere in an editor assembly that references Shipready's editor assembly. The Checker finds it by itself.

public sealed class CreditsRule : ReadinessRule
{
    public override string Id => "mygame.credits";
    public override string Title => "Credits are filled in";
    public override ReadinessArea Area => ReadinessArea.Screens;

    public override void Check(ReadinessContext context, List<ReadinessFinding> into)
    {
        if (CreditsAreEmpty())
            into.Add(Warning("The credits are empty", "Players and stores expect them.", "Fill in the Credits asset."));
        else
            into.Add(Passed("The credits are filled in"));
    }
}

For a check done by hand, derive from ReadinessManualCheck (or use GuidedCheck) and list the steps.
