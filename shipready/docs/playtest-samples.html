Docs/Shipready/Playtest

Samples

Two demo scenes, in Samples/Scenes. Open either with Tools > Shipready > Playtest > Open Demo. They draw correctly in Built-in, URP and HDRP with no setup, and use only Shipready's own shader and plain blocks.

Bug Hunt #

You're testing "Crate Delivery", a tiny game about to ship with real bugs in it.

  1. Press Play, then trigger a bug: - Deliver the crate: the crate falls through the floor and the delivery throws an error. - Collect pay: gold goes down instead of up, and a warning is logged. - Flip the lamp switch: the lamp flickers forever.
  2. Press F8. The form opens with the screenshot taken before it appeared and the steps filled in from what you did. Write a line, mark the screenshot, and save.
  3. Stop playing and open Tools > Shipready > Playtest > Report Inbox. Pick the report, click a stack line to go to the broken line in BugHuntDemo.cs, and press Go to where the tester was.

The report also holds the last seconds as pictures, the gold value and crates delivered as game state, and the recent events ("Pressed Deliver", "Walked to the shelf").

Feature Gallery #

One button for each thing Shipready can do, with the line of code behind it shown after you press it:

  • Open the report form, open the debug overlay, save a report with no form.
  • Switch between the four themes live.
  • Add a recent event, set a game state value, log a warning or an error.

Open the overlay (the key above Tab) and look at the Options tab: the spinning block's switch and speed come from [DebugOption] fields in FeatureGalleryDemo.cs with no UI code. In the console, type help, hello Sam or spin off to try the [DebugCommand] methods.

Using the samples in your own project #

The sample scripts are in their own assembly, so deleting the Samples folder removes them cleanly. Nothing else in Shipready uses them.
