Player Options

One asset where you decide what players get: which settings they see and may change, what they may do with saves, whether they can skip tutorials, and which builds carry the tester tools. Every Shipready screen asks this asset before it shows or allows something.

Make it #

Launch Desk > Player Options > Create Player Options. The asset is ShipreadyPlayerOptions in Assets/RareGeometryData/Shipready/Resources; the game loads it by that name. With no asset, players get everything except the tester tools in release builds.

Start from #

Starting point For What it does
Locked down A tightly directed game Sound, controls and accessibility only; graphics and display hidden; the game does the saving
Standard Most games Every setting and the save tools; tester tools stay out of release builds
Full control Early access, public tests Standard, plus turning autosave off and bug reports in every build

Settings players get #

The list shows every setting of your settings profile. For a whole category or for one setting choose:

Choice Players
Players change it see the setting and can change it
Shown, locked see the setting, dimmed, and cannot change it. It runs at your starting value
Hidden do not see it. It still runs at your starting value

Open a setting's row for more:

  • Starting value: the value it starts at and resets to. On or off, one of its options, or a number in its range.
  • Limits: the lowest and highest value players may pick, or which options they are offered.

A setting's own choice wins over its category's.

Saves, controls, tutorials #

Tick boxes for: save by hand, quicksave, name saves, copy saves, delete saves, restore a backup, turn autosave off, change keys and buttons, skip a tutorial, replay tutorials.

Tester tools #

Which builds have the bug report form and which have the debug console and options: none, development builds only, or every build. The Readiness tab tells you when these and the playtest settings disagree.

From code #

if (PlayerOptions.Current.Can(PlayerAction.SaveByHand)) ShowSaveButton();

// Ask and tell the player why not: raises PlayerOptions.Refused with a short reason.
if (!PlayerOptions.Current.Check(PlayerAction.DeleteSaves)) return;

PlayerOptions.Refused += (action, reason) => toast.Show(reason);

// Another set of options from now on, for example per difficulty.
PlayerOptions.Use(hardcoreOptions);

PlayerOptions.Current is never null. AccessFor(settingId, categoryId) gives a setting's access, RuleFor its starting value and limits.
