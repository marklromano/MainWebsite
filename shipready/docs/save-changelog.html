Docs/Shipready/Saves

Changelog

The same list is in CHANGELOG.md in Shipready's folder, which is the original; this page is a copy for reading here and offline.

This page lists every version of Shipready and what changed in it, newest first. Questions go to Discussions or the address in Tools > Shipready > Saves > Help, bugs to the bug report form. Documentation: https://raregeometry.github.io/.

[1.0.0] - 2026-10-30 #

First release. Everything in the two release candidates below, plus the changes here. Saves from the release candidates load as they are; there is nothing to do when you update.

Added #

  • Your own background pictures. The Menu Theme takes your own sprites behind the buttons, the main button, the panel and confirmation, and the slot cards (Menu Style window, Text and shape, Images, with the live preview). A sprite with borders set in the Sprite Editor is 9-sliced, and each picture is tinted by its part's colour. Keep Own Image on a Themed Element keeps a picture you set on one part by hand. Switching style keeps your pictures; a style file leaves them out, because they are your project's own assets.

[1.0.0-rc2] - 2026-10-26 #

Second release candidate: the same saving engine, with a much easier first ten minutes. Nothing here changes how saves are written, so saves from the first release candidate load as they are.

Added #

  • Start window (Tools → Shipready → Saves → Start). It opens once after import and offers three guided choices: make objects remember their state, add a save and load menu, or save values from your scripts. A status strip checks what a first save needs (settings, a saved scene, Build Settings, test hotkeys) and fixes each with one click.
  • Play Mode note: in the Editor, a short note in the Game view after every save and load says what was saved, what came back, and what was skipped and why. Click it for the full report.
  • Saveable summary: the top of each Saveable says in one sentence what it saves, and warns when your script's Start may reset a value right after a load.
  • Report a Bug (Tools menu and Start window): copies a ready-to-paste report of your setup, with no file paths or saved values, and shows the bug report form's address to copy.
  • Help and support page in the Start window: Shipready's version, its documents, the Discord, bug tracker, website and e-mail address to copy, Copy system info for a question or a bug report, and a Show this window when the project opens switch (off by default).
  • Walkthroughs: five illustrated step-by-step pages (first save, world objects, the save menu, game updates, backups and recovery), plus Support and Known Issues pages.
  • README.md, LICENSE.md, Third-Party Notices.txt and package.json in the Shipready folder.
  • Make it yours (Tools → Shipready → Saves → Menu Style, and the Start window): six ready-made menu styles (Dark, Light, Fantasy, Sci-fi, Cozy, Minimal); every colour, the font, sizes and corners; a list or a grid of 2 to 4 tiles, card height, which details a card shows, the panel's place and width, the title and the dimmed backdrop; every word, with its {0} rule explained; and export and import of a whole style as .json. A live preview shows each change without touching the scene. Changes go into your own copy in Assets/RareGeometryData/Shipready/Menu, never the Shipready's assets, and each is one undo step. The defaults are the menu's original look.
  • Game presets on the Setup Wizard's first page and the settings' Basics tab: Story / RPG, Roguelike, Arcade / mobile or Custom. Each lists exactly what it changes before you apply it, and never touches the passphrase, the save folder or file names.
  • Sounds, keys and your own UI: the save menu's Events (opened, closed, selection moved, question asked, saved, loaded, deleted, restored, failed) take sounds or effects without code; its Close Key and Close With Gamepad choose how players back out; its Confirmation field takes your own question box (ISaveMenuConfirmation). Any part can have its own colour or font size (Override on its Themed Element). Fade-in and button timing are part of the layout. The demos have a Style button (and T) that cycles the six styles live.
  • Own Menu demo and walkthrough: a save menu of your own, built in one short script on the public API (list the slots, save with a picture, load, delete).
  • Own Menu (UI Toolkit) demo and walkthrough: a save menu of your own in UI Toolkit, with a UXML layout, a USS style sheet and one short script on the public API (slots with picture, name, date and playtime; save, load, delete and Continue). No package is needed.
  • Continue, New Game and Quit with no code: the Game Menu prefab is a title screen or pause menu (Continue, New Game, Save Game, Load Game, Delete All Saves, Quit) in the menu's theme and words. Continue greys out while there is nothing to load; Quit and New Game ask "without saving?" when there is unsaved progress; Delete All Saves always asks. New calls: SaveKit.LoadMostRecent() (and Async), HasAnySave, GetMostRecentSaveInfo(), HasUnsavedProgress, UnsavedProgressSeconds, TimeSinceLastSave, DeleteAllSaves(includeGlobal), CopySlot, RenameSlot and KindOf.
  • Saving indicator for builds: "Saving..." with a turning icon in a corner while a save runs, then "Saved". Its colours, words, corner, timings and which saves show it are yours; it is on in the demos and absent from a new game until you add SavingIndicator.prefab.
  • Save menu: Load menu tabs (All, Saves, Autosaves), newest first, player-named saves with Rename on a card, and Copy into the first empty slot. All four are off by default; their words are in the Words tab. Your own confirmation can take names through ISaveMenuNamePrompt.
  • No-code components: Save Actions (Save To Slot, Load Slot, Quicksave, Quickload, Autosave, Continue, New Game, Delete Slot, Delete All Saves for any UnityEvent), Save Events (the save and load events as UnityEvents) and Save Point (a checkpoint trigger with a cooldown and an only-once option).
  • Component savers: Animator (parameters, and each layer's state and progress), Audio Source (playing, time, volume, pitch), Enabled (the tick box of chosen scripts, renderers and colliders) and NavMesh Agent (position, destination, speed, stopped). Add one beside a Saveable; no code.
  • Visual Scripting nodes and a Unity Localization hook (Localized Menu Text), in two optional assemblies that compile only when their package is installed. Shipready still needs neither package.
  • MenuTheme.Layout (MenuLayout), SlotListLayout, and the theme assets in UI/Settings/Styles. The menu's card list now lays out with SlotListLayout instead of a VerticalLayoutGroup; a prefab variant that changed that group's settings needs them set again on the new component.
  • Display as for every message the player sees: the saving indicator, the save notes, the status and co-op lines and the badges each show as full text, short text, an icon, the icon in its state's colour, the icon with short text, or nothing. Set it for the game in Menu Style's new Messages tab, for one kind of message, or on a part's own Inspector, where Display as and Position now sit at the top with a live preview. The demos' Y key tries each way, live.
  • A built-in icon set, drawn by Shipready in one even line weight and crisp at any size: a turning ring, a tick, a tray, a ring with "!", a cracked page, a clock turning back, chasing arrows, a bolt, an arrow up, two people, a padlock and an "i". Each can be swapped in the theme.
  • State colours in the theme (Saving, Saved, failures, co-op, locked, other news), set by each of the six styles.
  • Save notes (SaveNotes.prefab): a short note when a load finished, a save came back from its backup, or a save or load did not work. The demos have one.
  • Positions for the saving indicator and the notes: the four corners, the middle of the top or bottom edge, or any point, with a margin; a box glides to a new place. The demos' P key tries them.
  • Fits every screen: the menus, questions, indicator and notes now scale with the Canvas Scaler's Expand mode, so the whole design fits on 720p to 4K, 21:9 ultrawide, 4:3 and phones held upright, and a new Safe Area Panel component keeps them clear of a phone's notch and a TV's overscan (the dim backdrop still covers the whole screen). Both Own Menu demos do the same.
  • A phone layout: on a screen held upright, the menus are drawn for a phone (Menu Style, Layout, Phones held upright: Auto, the default). Words and buttons are as big as a phone needs, the save menu fills the width with one column of tiles, the Game Menu takes most of the width and questions fit the screen. It changes when the phone turns. Landscape rules keeps the wide layout scaled down; Custom sets the phone layout's width.
  • Every window fits a narrow panel: the Start window, Setup Wizard, settings, Menu Style, Save Inspector, Diagnostics and Shipready's inspectors work from about 150 points wide (a 300-pixel panel at 200% Editor UI scaling) up to wide: tabs wrap or become a dropdown, headings wrap, labels go above their fields, rows of buttons drop to fewer columns with no gaps, long labels end in "..." with the full text in a tooltip, and long lists scroll. Below the narrowest width a window scrolls sideways instead of squashing its text. Diagnostics has a full-width Run button above its Check: switches. Every window lays itself out in the height it really has below its tab, so the Setup Wizard's buttons are always in the window, and a short Save Inspector scrolls instead of squashing the open save. The open save's values are shown whole, wrapped, and a save's date is never broken across two lines; the open save's names and the Recent saves heading wrap rather than being cut. A foldout's title wraps across its whole row and never runs into the row below, and a save's name is never cut: its badges go on a line of their own when both do not fit.
  • The Game Menu's title: the game's name (or your own title) and an optional line under it, each with an off switch, shown in Menu Style's new Game menu preview. An empty Game Menu title used to mean no title; it now shows the game's name. Switch it off in Menu Style, Layout, The Game Menu, to keep a Game Menu without one.
  • Escape backs out of the Game Menu as it does the save menu: it closes the menu's question first, then a pause menu (one with an open and close key). A title screen stays open. The key (Close Key, Escape by default, or none) and the gamepad's back button are settings.
  • Open Demo asks once: its Build Settings question offers Add all demo scenes, so no other demo asks again (or Just this one, or Not now).

Changed #

  • Setup Wizard down to two steps: where saves go, and the menu with its hotkeys. Everything else moved to the settings asset's new Advanced tab; its Basics tab uses plain words.
  • F5 / F9 test hotkeys now come with the menu and work in the Editor only by default, with a setting for Editor and builds, or off.
  • Missing packages: Shipready no longer offers to install Unity UI or TextMesh Pro itself. It explains how to install them in a Console message and in Tools → Shipready → Required Packages, which opens the Package Manager on them. No dialog opens by itself.
  • Nothing opens outside Unity: Shipready never opens a browser, a file explorer or another program. Addresses and folder paths are shown to copy: the Save Inspector's Copy folder path and Copy file path, and the Saveable's Select script, which selects your script in the Project window.
  • Documentation: a five-minute Quick Start, and the Manual split into a Guide (how to do each task) and a Reference (how each part works).
  • The Saveable inspector uses plainer words; its id and category sit in a collapsed Advanced section.
  • Every kit inspector in one style: a line at the top says what the component does, then plain headings and grey help lines, with no Script row. Tick boxes have their label on the right, and a label that does not fit a narrow Inspector goes on its own line above its field instead of being cut. UnityEvents sit in a collapsed Events: sounds and effects, no code needed section, and the objects a generator linked up in a collapsed Advanced: parts the generator made section, with a warning above it when one is missing.
  • Savers: the Animator, Audio Source and NavMesh Agent savers start with this object's component filled in. The Enabled Saver has an Add this object's components button. A scene's name is picked from your scenes, with a warning when the scene is not in Build Settings.
  • Menu Theme and Menu Text assets: ready-made styles first, then a collapsed section per part. Colours sit two to a row when there is room, and questions get a box that wraps. Shipready's own theme and words show read-only, with a button to make your own copy.
  • Menu Style with no menu in the scene edits your project's own look, which every save menu you add afterwards gets, including from the Setup Wizard.
  • Save Inspector: with no saves it says "No saves yet. They appear here after the first save." Stacked, the list keeps at least 40% of the window, and the search box fills its row.
  • Setup Wizard: Shipready settings folder has its own heading, and the Back and Next buttons stay inside the window at any height.
  • Tidier windows at every width: tabs share one width and wrap onto rows, then become a dropdown; rows of buttons share one width or stack; windows scroll rather than squash; labels in a section line up in one column; and the inspectors use plain words with a tooltip on every field, such as Players can name their saves and Keep it when a new scene loads.
  • Open Demo (Tools > Shipready > Saves > Open Demo): every demo scene, with the World demo marked "(start here)". It asks to save the open scene first and offers to add the demo to Build Settings.
  • World demo: Quicksave (F6), Quickload (F7) and Autosave now buttons, so you can see those saves happen. The demos' buttons and steps name a key only while that key works in your build.
  • Game Menu: Quit is never the button picked first when the menu opens, unless it is the only one.
  • The Game Menu's title always fits: a long game name shrinks, then wraps onto a second line, and only then is cut off. Any themed label can do the same with its new Shrink To Fit tick box (off by default).
  • Demos: nothing on screen covers anything else. The saving indicator and the save notes have the top and bottom of the screen to themselves at every one of their places, messages sit beside the steps rather than over them, and the Game Menu shows Shipready's name as its title.
  • No more TextMesh Pro "Ellipsis is not available" warnings: text that runs out of room ends in "…" when the font has that character, and is cut off cleanly when it does not. On Unity 6.6 and later it is always cut off: that version's TextMesh Pro warns about "…" even in fonts that have it.
  • A damaged save's card said "A backup is ready to restore" while offering Load, which takes the backup by itself (Automatic Fallback). It now says "Load uses its newest backup", a line you can change in Menu Style like every other word.
  • Keyboard and gamepad focus shows as a ring in the style's accent around the button. Only the primary action keeps its filled colour, so a focused Cancel no longer looks like the button to press.
  • The per-save Console line ("Save slot_01.save: 12.4 ms, ...") is off by default, so the Console stays quiet. Every report is still in the Save Inspector's Recent saves and loads. Upgrading: a settings asset made before keeps its own choice; to switch the line off, untick Log each save (Report To Console) under Basics in the settings.
  • One message per save: the Editor's Play Mode toast says nothing the game's own save notes already say, and when it has more to say (a warning) it sits clear of them. The demos' own lines say "Slot 1", "the quicksave" or "an autosave", never a file name.

Fixed #

  • A Console warning on every Play about two migrations marked for the same version: automatic migration discovery found Shipready's own test fixtures. It now skips test assemblies (any that use NUnit), so a game only ever gets its own steps.
  • Start and Save Inspector open at a comfortable size (about 640 x 720 and 1000 x 640, as much as the display holds) when the size Unity remembered is cramped or smaller than their minimum, which also stopped them being resized by their corner.
  • Menu Style in a demo scene says it is a demo that builds its own menu on Play (T switches its styles there) instead of "No save menu in this scene", and that the look set here is the one your own scenes use.
  • Menu Style's status line clears after Edit > Undo, so it never says a style is in use once it has been undone.
  • The World demo's P key names the places in words ("top left") and no longer shows a "Game loaded" note, which read like a real load. A load that went well is left to the save note.
  • The Play Mode toast says nothing over an open save menu that shows its own status line.
  • Opening a demo then answering the Build Settings question marked the demo as modified, so switching demos or quitting asked to save a scene you had not touched.
  • The World demo's how-to steps, hidden with H, came back after a load that brought the courtyard back.
  • Demos in URP builds: every 3D object in the demos was invisible in a built game using URP, because the lit shader the demos ask for was left out of the build. It is now always included.
  • Menu text in a new project: in a project without TextMesh Pro's essential resources, the Start window said "Ready" while the save menu and the demos showed no text. The status strip now has a fifth check, Menu text ready, whose Import adds TextMesh Pro's resources straight away; Diagnostics warns about it with the same fix, and opening a demo scene without them asks once per session whether to import them.
  • Easier to read: the Setup Wizard's last page wraps its lines and puts its buttons on two rows when the window is narrow; settings labels fit Unity's standard Inspector width (Every (seconds), Log each save, Code values in, Objects in); the Save Inspector shows a saved position, rotation and scale on one row, the playtime as a clock time, and the time of each recent save and load; the Load menu lists the slots that hold a save before the empty ones; the demos' instructions shrink to stay clear of the buttons on short screens.
  • A damaged save's card is named for its slot and fills its lines like any other card: what is wrong ("This save can't be read") and whether a backup is ready. Its Restore button takes Load's place and style in the Load menu, and a button that could never work (Load on a damaged save or one from a newer version) is no longer shown greyed out. Every card button is one width.
  • Badge colours: Restored is now amber and From a newer version violet in every style, so Restored no longer looks like a success. A theme of your own keeps its colours.
  • The saving indicator's words in Full text are now whole sentences ("Saving your game..."); its default display, icon and short text, still shows "Saving...", "Saved" and "Save failed". An indicator set up with another corner, margin, or with words or icon off keeps that look. The Restore button now says "Restore". Words in your own Menu Text are kept.
  • Cleaner menus: every slot card is the same size and shape whatever it holds (a damaged save, an empty slot, an autosave), with its name, details and badges in the same places; the Damaged badge is the same small label as Autosave; long names, places and summary lines end in "..." instead of spilling out; every button in the save menu, its questions, the name box, the tabs and the Game Menu is one height with one gap. The selection outline fades with the Button colour change time, and the Game Menu and the questions fade in with the menu's Fade-in time. Nothing to do: a menu made from Shipready's prefabs picks this up on update.
  • Smaller fixes: the status strip's columns are even and a disabled fix says why; the Start window opens at a size that fits it; the windows are named Saves, Setup, Diagnostics and Inspector; Fix all shows only when something can be fixed at once.

[1.0.0-rc1] - 2026-10-16 #

First release candidate.

Added #

Platforms and Unity versions. Windows 10 and 11, 64-bit, with Mono and IL2CPP. Supported from Unity 2022.3 LTS; tested on Unity 6.3 LTS and the newest Unity 6. The co-op sample needs Unity 6 with Netcode for GameObjects 2.x. Render pipelines: Built-in, URP and HDRP. The core has no rendering code. Demos are checked in Built-in and URP; HDRP gets automated tests only. Input from the Input Manager, the Input System or both. No third-party dependencies: the menu uses Unity's own uGUI and TextMeshPro. macOS, iOS, Android, Linux, WebGL and consoles are not supported in 1.0.

Saving

  • SaveKit: one call each to save, load, delete and list saves, as blocking calls (for quitting) and async calls, plus SaveInBackground / LoadInBackground with a callback for slots. Autosaves, the quicksave and the global file have blocking and async forms too.
  • 10 manual slots by default (1 to 99), 3 rotating autosave files (1 to 10) and an optional quicksave, off by default.
  • A global file for settings and anything else marked Global. Loading a slot never overwrites it.
  • Categories: Settings (Global), Progress, Inventory, Quests and World (Slot). Rename them or add your own. Saves and loads can include all categories or only some, such as a checkpoint that saves Progress and World.
  • SaveKit.Data for plain values: numbers, text, true/false, dates, GUIDs, byte arrays, enums (stored by name), Unity vectors, rotations, colours, rectangles and bounds, lists and arrays, dictionaries with text or whole-number keys, and your own [Serializable] classes.
  • Autosaves on a timer, on scene change and on quit. Each trigger can be switched off, and so can autosaving during a cutscene.
  • Slot info: date and time, playtime, location, game version, a 320×180 thumbnail and up to four summary lines. A save without a new picture removes the old one, so a slot never shows a picture of an older save.
  • Events: Saving, Saved, Loading, Loaded and RecoveredFromBackup.
  • With the async and callback calls, packing and disk work run on a background thread, one queue per file. Every stage shows up in Unity's Profiler under its own marker (Shipready.Save.Capture, Shipready.Save.Write and ten more).
  • Shipready starts by itself from the settings asset, or from your own SaveKit.Initialise call. A profile folder of {profile}, filled in from SaveKit.ProfileId (such as a Steam ID), keeps two players on one PC apart.
  • Nothing throws into your game. Every call returns a result with an error code (SK001 to SK154), a plain-English message and a link to its Troubleshooting entry.
  • Logging levels Off, Errors, Warnings and Verbose, and a one-line report in the Console for every save and load (Report To Console, on by default).

World persistence

  • The Saveable component, with a permanent ID per object. Copies get new IDs automatically.
  • Built-in savers: Position (with parent), Active, Destroyed (destroy or disable) and Physics (Rigidbody and Rigidbody2D).
  • The Field Picker: tick the Inspector fields to save. Fields that cannot be saved are greyed out with the reason.
  • The ISaveable interface for custom scripts, with links to registered assets and to other saved objects.
  • Objects spawned at runtime from prefabs are re-created on load. The Prefab Registry keeps itself up to date, and pools need one line each way (SaveKit.World.Despawned and Spawned).
  • Links between saved objects and to registered assets such as ScriptableObjects are restored, and so are parents. A link to an object that no longer exists becomes empty, with a warning.
  • Multiple and additive scenes. Scene memory keeps the state of scenes the player has left, through SaveKit.LoadScene and SaveKit.UnloadScene or one line with your own scene loader.
  • DontDestroyOnLoad objects are saved in their own section.
  • State is restored after Awake and before Start. Restored rigidbodies are held still for one physics step.
  • Two load modes: load the saved scenes, or restore into the scenes already open. In the Editor, a saved scene that is not in Build Settings still loads, with a warning that a build could not load it; a saved scene that cannot be loaded but is open already, with the same id, gets its state restored in place (in a build, never for the first saved scene).
  • SaveKit.NewGame to start a fresh playthrough over an old slot, before loading the first scene or in the scene that is open. Shipready's own autosaves leave the scenes that were open at NewGame out of the save until a slot save or quicksave captures them, so an autosave never writes the old game's objects into the new game's save.

Recovery

  • Crash-safe writes: each save goes to a temporary file, is read back and checked, then swapped into place.
  • A checksum is verified on every load. A hand-edited readable save counts as damaged by default; moddable games can accept it with a warning.
  • Rotating backups: 2 per file by default (0 to 5).
  • A damaged file falls back to the newest good backup automatically, and the damaged copy is kept as .corrupt-<time> for support. Automatic fallback can be switched off in favour of a Restore backup action.
  • A full disk or a denied folder leaves existing saves untouched and says why.
  • Number formatting does not depend on the machine's language settings, so "1,5" never replaces "1.5". Floats and doubles come back bit-exact and are written in their shortest exact form, such as 0.8.

Game updates

  • Every file records the save format, your save version, your game version and Shipready version.
  • Migration steps: static methods marked [SaveMigration(fromVersion: N)], or steps added in code, run in order on load, with helpers to rename keys and categories, remove values and add defaults. A missing step gives MigrationMissing, and a save from a newer game version is refused with NewerVersion. In both cases the file is left untouched.
  • A build step writes link.xml so IL2CPP code stripping keeps every migration.
  • Tolerant loading: missing values use their defaults, saved objects that no longer exist are skipped and reported, and new objects keep their scene defaults. Renaming or moving a scene never breaks a save.
  • Changing compression or encryption in an update never strands old saves.

File options

  • Readable JSON by default: indented in the Editor and development builds, compact in release builds.
  • Optional GZip compression and optional AES-256 encryption with a tamper check. Slot info stays readable so the menu never decrypts a whole file, unless you choose to encrypt it too.
  • The global file can have its own options and its own file extension, for example to keep machine-specific settings out of Steam Cloud.
  • Your own storage plugs in through ISaveStorage. File storage and in-memory storage are included.

Player menu

  • One prefab with Save and Load modes.
  • Slot cards with thumbnail, name, date and time, playtime, location, two summary lines and badges: Autosave, Quicksave, Damaged, Restored and From a newer version. Autosaves and quicksaves take their own thumbnail from the main camera.
  • Save to a new slot or overwrite with confirmation, load with an optional "unsaved progress will be lost" confirmation, delete with confirmation, and Restore backup for damaged slots.
  • Mouse, keyboard, gamepad and touch, with either Unity input system.
  • Restyle it with one Menu Theme asset (colours, font, sizes, corner radius) and translate it with one Menu Text asset.
  • Test hotkeys: F5 opens the Save menu and F9 the Load menu.
  • Co-op clients see the cards without the save and load buttons.

Editor tools

  • Start window (Tools → Shipready → Saves → Start): opens once after import, with three guided choices (make objects remember their state, add a save/load menu, save values from scripts) and a status strip that checks the settings, the saved scene, Build Settings and the test hotkeys, each with a one-click fix.
  • Setup Wizard (Tools → Shipready → Saves → Setup Wizard): two steps, where saves go and the menu with its test hotkeys, then a list of everything it created or changed. Every step can be undone. Categories, file options, game updates and the scene scan are on the settings asset's Advanced tab.
  • Play Mode toast: in the Editor, a note in the Game view after every save and load says what was saved, restored or skipped, and opens the report when clicked.
  • Test hotkeys (F5 / F9) come with the menu and work in the Editor only by default.
  • Save Inspector: every save with its status, a searchable tree of its contents, highlighting in the open scene, a Play Mode live view, and import, export, restore backup, delete and copy the folder's path.
  • Diagnostics: finds duplicate or missing IDs, prefabs and assets missing from the registries, ticked fields that cannot be saved, scenes missing from Build Settings, the default encryption passphrase and unsupported build targets. One-click fixes where they are safe.
  • The Saveable inspector with the Field Picker; registry commands: Rebuild Registries and Register Selected Assets; and generator commands: Rebuild Menu Prefabs and Rebuild Demo Scenes.
  • Required Packages: in a project without uGUI or TextMesh Pro, Shipready imports without compile errors (its runtime and its core editor services, the saved ids, registries and migration link file, compile and keep working) and explains how to install the missing package in the Package Manager, once per project and from Tools → Shipready. Shipready never installs packages itself. A player build stops with the same message until the package is in.

Co-op

  • Host-only saving through ISaveAuthority. A client that tries to save, load or delete a slot gets a HostOnly result, and no slot file is touched.
  • Per-player data under a stable player ID from IPlayerIdentity, such as a Steam ID. It comes back when that player rejoins; new players start with defaults.
  • A spawn hook, ISpawnHandler, so the network library creates networked objects on the host.
  • Clients keep their own settings file.

Samples

  • Four demo scenes, built by an editor command: Quick Start, World (with a second scene to walk to and back), Game Updates and Recovery. They pick materials for the active render pipeline and show their instructions on screen. Demos are checked in Built-in and URP; HDRP gets automated tests only.
  • A co-op sample for Unity 6 with Netcode for GameObjects 2.x (Tools → Shipready → Saves → Samples → Build Co-op NGO Sample): host and join, a host world with spawned items, and per-player data that comes back on rejoin. It compiles only when NGO 2.x is installed, and was tested with NGO 2.13.3.

Documentation

  • Quick Start, Guide (task recipes) and Reference (how each part works), API Reference, Troubleshooting with one entry per error code, Game Updates, Co-op, Steam Cloud, Limits and FAQ, and this Changelog, each also as an offline HTML page.
