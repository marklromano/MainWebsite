Docs/Shipready/Saves

Steam Cloud

Steam Auto-Cloud copies the save files you choose to Steam's servers when the player quits. When the game starts again, on any PC, Steam copies them back. You set it up on the Steamworks partner site. It needs no game code, and Shipready works with it as it is.

This guide gives the Auto-Cloud settings that match Shipready's folders and file names. Steam's own documentation is at partner.steamgames.com/doc/features/cloud.

Scope. Shipready 1.0 is tested on Windows, so this guide covers Windows builds. Shipready has no built-in cloud sync and never talks to Steam. Steam does all the copying.

Before you start #

Choose these names before your first release. Changing any of them later makes Shipready look in a different folder or for different files, so existing saves seem to disappear (see SK100):

  • Company Name and Product Name in Project Settings → Player.
  • Save Folder Name, Profile Folder, the file name patterns, File Options → File Extension and, if you use it, Global File Options → File Extension in the settings asset ShipreadySaveSettings.

Settings in bold, such as Save Folder Name, are fields on that settings asset unless the text says otherwise. Select the asset in the Project window to change them.

Step 1: Set the byte quota and the file count #

Steam keeps Auto-Cloud locked until both limits are set.

  1. Open your app's Steam Cloud Settings page on the Steamworks partner site.
  2. Fill in Byte quota per user and Number of files allowed per user.
  3. Click Save at the bottom of the page, then publish the change.

Choosing the file count. Each save is one file. Add up:

  • Slot Count (10 by default)
  • Autosave File Count (3 by default)
  • 1 for the global file, which holds the Settings category, unless you keep it on the PC (Step 4)
  • 1 for the quicksave, if Quicksave Enabled is on

With the defaults that is 14 files. Leave room to grow, for example 20. The most Shipready can ever write is 111 files: 99 slots, 10 autosaves, the global file and the quicksave.

Choosing the byte quota. Play far into your game, save, and note the file size. You can read it from the save result:

using RareGeometry.Shipready.Save;
using UnityEngine;

public class SaveSizeCheck : MonoBehaviour
{
    public async void SaveAndMeasure()
    {
        SaveResult saved = await SaveKit.SaveAsync(slot: 1);
        Debug.Log("Slot 1 is " + saved.Report.FileBytes + " bytes.");
    }
}

Multiply that size by your file count, then double it for growth. Turning on File Options → Compress makes saves much smaller, because JSON usually shrinks several times.

Steam counts the quota for each player and each game separately. Backups, thumbnails and Shipready's other working files do not count toward it, because they never sync (see Step 5).

Checkpoint: the Auto-Cloud section now appears on the Steam Cloud Settings page.

Step 2: Add the Root Path #

On Windows, Unity keeps each game's files in this folder, which is Application.persistentDataPath:

%USERPROFILE%\AppData\LocalLow\<Company Name>\<Product Name>

Shipready saves into the Save Folder Name folder inside it, which is Saves by default. In the Auto-Cloud section, add one Root Path:

Field Value
Root WinAppDataLocalLow
Subdirectory <Company Name>/<Product Name>/Saves
Pattern *.save
OS [Cross-Platform], the default
Recursive Off
  • Subdirectory: copy Company Name and Product Name exactly as they appear in Project Settings → Player. For example, the company MyStudio and the product Star Farm give MyStudio/Star Farm/Saves. If you changed Save Folder Name, use your folder name instead of Saves.
  • Pattern: *.save matches Shipready's default File Options → File Extension. If you changed the extension, change the pattern to match, for example *.sav.
  • OS: Steam recommends Cross-Platform even for a game that ships on one platform, because files locked to one platform do not sync to others if you add platforms later.
  • Recursive: leave it off. Only the files in that one folder should sync.

Click Save, then publish the change.

Find the exact folder. Set Log Level to Verbose in the settings asset and press Play. When Shipready starts, the Console shows a line like this:

[Shipready] Ready. Saves are kept in C:/Users/<you>/AppData/LocalLow/MyStudio/Star Farm\Saves.

The mix of / and \ in that line is normal on Windows.

You can also log it yourself with Debug.Log(SaveKit.Storage.DescribeLocation()); once Shipready has started. On Windows, the Editor and a build use the same folder.

Checkpoint: %USERPROFILE%\AppData\LocalLow\ followed by your Subdirectory gives exactly the folder that the Console line shows.

Step 3: Give each Steam user their own folder #

Two people can share one PC with two Steam accounts. If both accounts use the same save folder, they share one set of saves, and Steam uploads the same files into both accounts. Two placeholders, one on each side, keep them apart:

  • On Steam's side, the Subdirectory may contain {64BitSteamID}. Steam replaces it with the signed-in user's 64-bit Steam ID, such as 76561198000000000.
  • On Shipready's side, Profile Folder set to {profile} puts the saves into a folder inside the save folder, named after SaveKit.ProfileId. Your game sets SaveKit.ProfileId to the same 64-bit Steam ID, so both sides name the same folder: Saves/76561198000000000.

Shipready never talks to Steam and never fills in {64BitSteamID}: that placeholder only means something in Steamworks. Shipready only knows the ID your game gives it.

  1. In Steamworks, change the Subdirectory to <Company Name>/<Product Name>/Saves/{64BitSteamID}. Keep Recursive off. Click Save, then publish.
  2. In the settings asset, set Profile Folder to {profile}, and switch Initialise Automatically off (in the wizard: Profile folder (optional) in the first step, and Start Shipready by itself in the second).
  3. In your game, once Steam is running, set SaveKit.ProfileId to the player's Steam ID, then start Shipready.

Why Shipready must wait. With Initialise Automatically on, Shipready starts just before the first scene loads, before any of your scripts' Awake runs, and it reads SaveKit.ProfileId only at that moment. With {profile} in Profile Folder and no ID set yet, it refuses to start (SK153) rather than mix two players' saves, and the Console shows "Shipready could not start by itself". So switch automatic start off and start Shipready yourself, like this:

using RareGeometry.Shipready.Save;
using UnityEngine;

// Settings asset: Profile Folder = {profile}, Initialise Automatically off.
// Put this on an object in the first scene, after your Steamworks integration has started.
public class SaveKitSteamStartup : MonoBehaviour
{
    void Start()
    {
        if (SaveKit.IsInitialised) return;

        // The same number Steam puts in place of {64BitSteamID}. Without Steam, for example
        // in the Editor, use a fixed name so Shipready still starts.
        string steamId = GetSteamId64();
        SaveKit.ProfileId = string.IsNullOrEmpty(steamId) ? "local" : steamId;

        SaveResult started = SaveKit.Initialise();
        if (!started.Success) Debug.LogError(started.ToString());
    }

    static string GetSteamId64()
    {
        // Ask your Steamworks integration for the signed-in user's 64-bit Steam ID and return
        // it as a plain number, for example "76561198000000000". Return an empty string when
        // Steam is not running.
        return string.Empty;
    }
}

This uses Start so that a Steamworks integration that starts in Awake is ready first. Any save or load before this runs returns NotInitialised (SK005), so start Shipready before your game's first save, load or save menu.

Keeping automatic start on instead. Unity runs a static method marked [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)] before Shipready starts by itself. If your Steamworks integration can give you the ID that early, set SaveKit.ProfileId there and leave Initialise Automatically on. Do not use SubsystemRegistration, where Shipready clears the ID for each new Play session in an order you cannot control, or BeforeSceneLoad, which may run after Shipready has already started.

Notes:

  • The ID must be the plain decimal number, the same value Steam uses for {64BitSteamID}.
  • When Steam is not running, the code above saves into Saves/local. Steam never syncs that folder, because its Root Path points at the ID folders.
  • SaveKit.ProfileId may hold letters, digits, - and _. A Steam ID is all digits.
  • To switch to another Steam user while the game runs, call SaveKit.Shutdown(), set the new ID and call SaveKit.Initialise() again. Shutdown also removes your SaveEvents handlers, so add them again afterwards.
  • Decide on profile folders before release. If you add them in an update, existing saves stay in Saves and seem to disappear (see SK100).

Checkpoint: after a save, the save folder contains a folder named after your Steam ID, and slot_01.save is inside it. With Log Level on Verbose, the Console line from Step 2 ends with that folder.

Step 4: Keep device-specific settings local #

Steam advises against syncing machine-specific settings such as video quality. A laptop and a gaming PC need different values.

In Shipready, the categories marked Global (Settings by default) are kept in the global file, which is global.save by default. That name matches *.save, so it syncs. That suits preferences that should follow the player, such as subtitles, key bindings and volume. It does not suit screen resolution, graphics quality or the chosen monitor.

Keep the global file on the PC by giving it its own extension. The global file can have file options of its own, including its own extension. An extension that does not match *.save, such as .local, keeps it, and every working copy of it, on the PC:

  1. Select the settings asset and open its Advanced tab, Packing, encryption and backups. Under Shared file, tick Write it differently (in code: untick Use Slot Options For Global File).
  2. Set its File extension to .local, then click Apply the file options. Leave the other options as they are, or choose how the global file is packed: Indent the text, Compress, Encrypt and Older copies kept apply to it alone.

The global file is then global.local, with global.local.tmp and global.local.bak1 beside it, and none of them match *.save. Encryption, if you switch it on for the global file, uses the passphrase, salt and iterations from File Options, so every file of your game shares one key.

  • Everything Global stays on the PC. Shipready has one global file, so every Global category goes with it. If you want some preferences, such as key bindings, to follow the player while graphics settings stay on the PC, keep the global file syncing instead and store the machine-specific values in PlayerPrefs. On Windows, Unity keeps PlayerPrefs in the registry, not in the save folder, so Steam never syncs them.
  • The extension needs a dot and a few letters. It cannot be .tmp or start with .bak or .corrupt, which Shipready uses for its own copies. Otherwise Shipready refuses to start (SK153).
  • Switching in an update is safe. If a game update gives the global file its own extension, Shipready loads whichever of global.save and global.local was written last, so players keep their latest settings, and the next save writes global.local. The old global.save is left where it is, and Steam keeps the copy it already has; Shipready ignores it once global.local is newer.

Checkpoint: after the player changes a setting and the game saves the global file, the save folder holds global.local and no newer global.save.

Step 5: What stays local #

Every file Shipready writes for slot 1 is listed below. Only files that end in .save match the pattern *.save.

File What it is Synced by *.save
slot_01.save The save Yes
autosave_1.save to autosave_3.save The rotating autosaves Yes
quicksave.save The quicksave, when it is switched on Yes
global.save The Global categories, such as Settings, while the global file uses the slots' extension Yes
global.local The same file, when Global File Options → File Extension is .local (Step 4) No
slot_01.save.tmp A save that was still being written No
slot_01.save.bak0 The file being replaced, for a moment during a save No
slot_01.save.bak1, slot_01.save.bak2 Backups, newest first (up to .bak5 with Backup Count 5) No
slot_01.save.corrupt-20261102-184107-123 A damaged copy, kept for support (the time is UTC) No
slot_01.save.thumb.png The thumbnail the save menu shows No
slots.index Shipready's cache of slot info No

Autosaves, the quicksave and the global file have the same kinds of working files, for example global.save.bak1, or global.local.bak1 when the global file has its own extension. With a profile folder (Step 3), all of these sit in the player's ID folder.

Here is why Shipready names its files like this:

  • Uploads stay small. Only the real saves count toward the quota and the file limit.
  • Backups stay a local safety net. If a save cannot be read, Shipready falls back to that PC's own backups as usual.
  • Half-written and damaged copies never travel. The .tmp and .corrupt- files only make sense on the PC that wrote them.
  • The slot cache stays correct. slots.index records each save's size and time, and Shipready uses an entry only while both still match. A save that Steam has just downloaded is therefore read fresh.

Thumbnails. Thumbnails stay on the PC too. On a second PC, a synced slot shows that PC's own older picture for the slot, or no picture, until the player saves that slot there. To sync thumbnails as well, add a second Root Path with the same Root and Subdirectory and the pattern *.thumb.png. Each thumbnail is a 320×180 PNG and one more file, so raise the file count and the byte quota to match.

Step 6: Test #

Steam's test steps:

  1. Sign in to Steam with an account that owns the game. If the game is already released, you can tick Enable cloud support for developers only while you test. Then only accounts with a developer licence for the game see the change.
  2. Open the Steam console by entering steam://open/console in your web browser.
  3. In the console, enter testappcloudpaths <AppId>, for example testappcloudpaths 480.
  4. Enter set_spew_level 4 4 for detailed cloud logging.
  5. Start the game from Steam, save into a slot and quit. Steam uploads when the game exits. Watch the console.
  6. On a second PC, signed in to the same account, start the game. The slot shows the save from the first PC.
  7. When you have finished, enter testappcloudpaths 0 and set_spew_level 0 0, then restart Steam. If you used developers-only mode, switch it off and publish.

While you test, also check Shipready's side:

  • Only .save files sync. If the console shows .bak1, .tmp or .thumb.png files being uploaded and you did not add them on purpose, the pattern is too broad.
  • Steam users stay apart. Two Steam accounts on one PC each see only their own slots (Step 3).
  • Device settings stay put. With the global file kept on the PC (Step 4), the second PC keeps its own graphics settings, and the console shows no global.local upload.
  • Quitting saves first. With Autosave On Quit on (the default), Shipready finishes the quit autosave before the game exits, so Steam uploads a complete file.

Checkpoint: a save made on one PC loads on the other, and the second PC's save folder holds no .bak, .tmp or .corrupt- files that came from the first PC.

If nothing syncs #

  1. Check that the Steamworks changes were published. Then wait up to 10 minutes, or restart Steam.
  2. Read cloud_log.txt in the logs folder of the Steam installation, for example C:\Program Files (x86)\Steam\logs\cloud_log.txt. It is Steam's own record of each sync.
  3. Compare the folder Steam uses with the folder from the Console line in Step 2. The usual causes are: - Company Name or Product Name spelled differently, including spaces and capital letters. - Save Folder Name changed in the settings asset but not in Steamworks. - Profile Folder set to {64BitSteamID}, which Shipready does not know, instead of {profile}. Shipready then writes into a folder that is literally called {64BitSteamID}. - SaveKit.ProfileId set to something other than the plain 64-bit Steam ID, such as a 32-bit account ID or the player's name, or set after Shipready had already started. - A pattern that does not match File Options → File Extension.
